# trid 개발 감독 및 작업 지침

## 현재 실행 계약 — PIPELINE-3-001

사용자가 승인한 현재 제품 방향은 **공개 가중치 소형 모델 기반의 공공기관·공기업 내부업무 특화 TRID**다. 정확도와 폐쇄망 운영을 우선한다. 자체 기초 모델 추가 대규모 학습은 보류하며, 이미 승인된 실험은 결과를 보존한다.

| 세션 | 단일 책임 | 인계 |
|---|---|---|
| B | 공개 데이터 병렬 수집·정제·학습 사례 준비 | 권리·시점·기관·검토 상태·중복·분할·해시를 포함한 고정 데이터 manifest를 A에 전달 |
| A | 모델 선정·학습·모델 아티팩트·배포 | 가중치·기반 revision·토크나이저·템플릿·학습 manifest·추론 조건을 C에 전달 |
| C | 고정 평가 실행·블라인드 채점·회귀 분석·실사이트 검증 | 원본 대비 결과와 한계를 총괄·A에 보고. 평가 원문·정답을 학습 데이터로 전달하지 않음 |

- 전환 중인 C의 학습 사례 작업은 현재 배치를 고정해 B에 인계한다. 파일 소유권 인계를 확인하기 전에는 서로 같은 빌더를 편집하지 않는다.
- 이미 실행 중인 평가·학습은 중복 실행하지 않는다. 기존 평가 산출물도 C가 검토한다.
- C가 이전에 학습 사례를 작성한 사실은 없어지지 않는다. 역할 분리는 이후 운영 경계이며, 기존 평가의 통계적 독립성이나 사람 검수를 보증하지 않는다.
- B의 병렬 작업은 출처별 출력 경로와 단일 통합 manifest 소유자를 분리한다. 동일 호스트의 요청 제한은 모든 작업자가 공유한다.
- 하위 AI 에이전트는 현재 제공자 429로 기동 실패했다. 같은 경로를 반복 호출하지 않는다. 당장은 서로 다른 출처의 CPU 수집 프로그램을 병렬 실행하며 이를 하위 AI 가동으로 표시하지 않는다.
- 추가 컴퓨팅 총 한도는 **300,000원**이다. 현재 예약은 A 90,000원, C 20,000원, B 0원이며 사용액과 예약액을 구분한다. 유휴 자원은 종료하고 재시도·추가 실행은 승인 범위를 따른다.
- 맥미니는 현재 임시 AWS 로그인과 감시 전용 제어기만 검증됐다. 루트 자격으로 자동 발행하지 않는다. 로그인 만료 시 재인증이 필요하며, 전체 개발·평가·사이트가 맥북과 독립했다고 표시하지 않는다.
- 완성된 실험 버전은 기반 모델과 검증 결과·제한사항을 표시해 테스트 사이트에 배포하고 롤백 경로를 유지한다. 제품 품질 합격과 실험 배포를 구분한다.
- Git에는 담당 파일만 작업 단위로 커밋한다. 공유 파일 소유권을 확인하고, 가중치·원문·자격증명은 포함하지 않는다.

## 이전 감독 기록 — 현재 실행 승인이 아님

**아래는 초기 역할·실험·승인 이력이다.** 외부 가중치 금지, 무제한 AWS 사용, C의 학습 사례 전담 등은 위 현재 계약으로 대체됐다. 과거 작업 ID와 상태는 당시 기록이며 현재 실행 상태로 해석하지 않는다.

## 목적과 권한

사용자 요청: 세 개발 세션의 작업 결과를 총괄 세션에서 검토하고 다음 작업을 지시한다.
최종 목표는 대한민국 공공기관·공기업에 도입할 수 있는 폐쇄망 전용 자체 LLM이다. 외부 사전학습 가중치를 제품에 사용하지 않으며, 명시한 더 큰 범용 비교 모델보다 작은 파라미터로 공공업무 벤치마크에서 더 높은 성능을 입증해야 한다. 단순 91M 대비 개선은 중간 단계이지 최종 성공이 아니다.
이 문서는 공통 지침이며 자동 실행기나 완료 알림 장치가 아니다.

현재 연결 상태: 세 개발 세션의 Collab control 접근과 실제 대화 기록을 확인했다. ROUND-001 역할 지시와 AWS-APPROVAL-001 추가 승인을 각 대화에 전달하고 표시됨을 확인했다. 제어 링크는 비밀이며 문서나 Git에 저장하지 않는다. 브라우저 연결 자체는 총괄을 자동 호출하지 않는다.

완료 감시: 지정 보고서의 READY 마지막 줄을 기다리는 작업별 1회 알림을 사용한다. 일반 작업은 약58분 후 미제출 시 timeout을 알린다. 장기 A-003 본비교는12시간 완료 감시(bg_13)를 사용하고 실제시작확인 A-003-launch(bg_12)를 별도로 기다린다. 현재 B-002(bg_6), B-003(bg_10), C-006(bg_11)도 감시한다. 결과가 총괄에 전달되면 검토·후속지시·감시를 이어 배정한다. 총괄 프로세스 종료 뒤 상시감독·무기한자동재시작은 보장하지 않는다.

후속 지시의 근거는 `reports/coordination/<작업ID>-review.md`에 보존한다. 최초 역할 설명과 후속 작업 범위가 다르면 최신 명시적 후속 지시를 따른다. A-002는 현재 데이터의 91M/390M MHA 동일 조건 20M 토큰 수치 안정성 파일럿이며, C-002는 최종 문맥 의미 검토 및 부족 과제 파일럿이다. 둘 다 실제 제품 성능 합격이나 배포 승인이 아니다.

A-002의 두모델20M토큰 안정성·재개 보고를 검토해 A-003을 승인했다. 신규91M/390M 각각1B토큰을 동일mix-v3/context1024 조건으로 병행학습하고 동일SFT·개발평가를 수행한다. 승인서는 `reports/coordination/A-002-review.md`. 20M파일럿가중치를1B스케줄에이어붙이지않으며 기본2시간deadline 대신명시적12시간deadline을쓴다. 실제Training시작은 A-003-launch 보고로확인하며 승인전달만으로실행중이라고표시하지않는다.

### AWS 자원 사용 승인

사용자는 총괄 세션에서 “aws 자원 마음껏 사용해도되니까 이거 참고해줘”라고 추가 승인했다. trid 개발에 필요한 GPU/CPU 실행, 저장 공간, 할당량 확보는 비용 발생 자체를 이유로 재승인을 요청하지 않는다. 자원 선택은 작업량·실측 처리량·검증 목적을 근거로 하고, 할당량이나 특정 인스턴스 부족은 대체 자원을 검토한다.
이는 평가 기준을 생략하거나 실패한 실험을 무한 반복하라는 지시가 아니다. 데이터 품질·실험 설계 검토는 계속 적용한다. 작업별 소유자·용도·종료 조건을 기록하고, 결과와 체크포인트를 내구성 있는 저장소에 보존한 뒤 유휴 연산 자원을 종료한다. 타 세션 작업, 기존 데이터 및 관련 없는 자원은 건드리지 않는다. 자격증명을 코드·로그에 넣거나 공개 접근을 허용하지 않는다.

추가 승인(AWS-CONTINUE-001): 사용자는 “목표 지표 도달할때까진 aws 계속 사용해줘”라고 지시했다. 목표 달성 전까지 AWS를 활용한 수집·정제·학습·평가의 개발 루프를 지속하며, 개별 작업 종료를 전체 개발 중단이나 비용 재승인 대기로 해석하지 않는다. 총괄은 결과를 검토하고 다음 가설·작업을 이어 배정한다. 즉시 실행 가능한 후속 작업이 있으면 기존 자원을 안전하게 재사용하거나 적합한 새 자원을 확보한다. 후속 작업이 없거나 사람 검수·사용권·원문 확보 등 외부 의존성으로 막혔을 때만 유휴 연산 자원을 정리하고, 다른 독립적인 준비 작업은 계속한다.
이 지시는 C-006의 “검증 완료 후 무조건 인스턴스 정지”보다 우선한다. 결과 저장·작업 소유권 확인은 유지하되, 종료 전에 총괄이 다음 실행 가능 작업으로 인계할지 확인한다. 이미 정지한 자원은 필요 시 재기동할 수 있으며, 데이터 보존이나 다른 세션의 실행 중 작업을 희생하지 않는다. 기준 미달 결과를 합격으로 바꾸거나 시험 결과를 본 뒤 목표 지표를 낮추지 않는다. 상시 감독은 총괄 세션이 살아 있고 완료 알림 연결이 유지되는 동안에만 가능하다.

## 최종 제품 목표와 비교 원칙 (DOMAIN-GOAL-001)

- 범위: 특정 기관 한 곳의 암기가 아니라 여러 공공기관·공기업의 규정·공고·업무 문서를 처음 받아 해석하고 근거와 함께 설명하는 능력. 보훈·부동산·복지·계약·인사·회계 등 기관과 업무 유형별 분포를 기록하고 일부 분야 평균으로 전체 공공영역 대응을 주장하지 않는다.
- 크기: 91M/346M/390M은 실험 후보이며 최종 제품 크기는 미확정이다. 더 작은 크기와 더 높은 공공업무 정확도를 함께 최적화한다. 비교 모델의 실제 파라미터 수·버전·양자화·하드웨어·메모리·지연시간을 명시한다.
- 비교 기준선: 현재 Qwen3-1.7B 및 Kanana-1.5-2.1B 결과를 출발점으로 사용하되, 기본 모델만이 아니라 기존 동등 도메인 튜닝 기준선도 포함한다. 비교군과 주지표·판정법은 최종 시험 전에 고정한다. 모든 기존 모델에 대한 보편적 우위를 근거 없이 선언하지 않는다.
- 평가 분리: (1) 동일 근거 문서를 주는 모델 독해·설명 평가, (2) 동일 문서 집합에서 검색부터 답변까지의 시스템 평가, (3) 폐쇄망 운영 검증. 검색 품질이나 제한 출력 문법의 이득을 모델 자체의 지능 우위로 바꾸어 설명하지 않는다.
- 공공업무 과제: 사실·금액·날짜 추출, 자격/조건/예외, 규정 개정·시점, 표·계산, 여러 문서 근거 결합, 근거 기반 설명, 근거 없음/충돌 대응. 결론·근거·조건의 정확성과 부가 허위 주장을 채점하고 짧은 값 형식만 잘 맞추는 평가로 설명력을 대체하지 않는다.
- 독립성: 기관·문서 묶음·시점 단위로 학습/개발/최종 시험을 분리하고 유사 문서·개정본 누출도 검사한다. 최종 시험은 학습 담당자에게 정답을 노출하지 않는다. 반복 사용한 RAG310은 개발 진단이다.
- 우위 판정: 실제 공공문서 기반 고정 시험에서 비교군 대비 개선과 불확실성을 함께 제시한다. 답 없는 질문에 계속 보류해 얻는 평균점수나 형식 준수만으로 승리를 선언하지 않는다. 태스크/기관별 성능, 오답·보류·환각, 설명 품질을 별도 보고한다. AI 판정은 독립 사람 검수와 구분하며 실제 도입 판정에는 공공업무 전문가 검수가 필요하다.
- 폐쇄망: 운영 시 외부 LLM/API·인증·원격 다운로드를 요구하지 않아야 한다. 가중치·토크나이저·검색·문서 처리·필요 패키지를 오프라인 배포하고 네트워크를 차단한 상태에서 실제 문서 질의를 검증한다. 권한별 문서 접근, 출처 추적, 개인정보·감사 기록도 도입 관문으로 다룬다. AWS는 개발/학습 수단이지 운영 환경의 외부 의존성이 아니다.
- 현재 A-002 수치 안정성 파일럿과 C-002 과제 보강은 이 목표를 위한 중간 작업이다. 진행 중인 작업을 폐기하지 않으며, 이 목표에 맞춰 이후 학습과 최종 시험을 설계한다.
- 평가 규모 보완(BENCHMARK-SCALE-001): 10~30문항은 실행·형식 점검 전용이다. 실제 공공문서 기반 2,000문항 성능 평가를 목표로 하며 기관·문서 다양성, 학습 제외, 독립 정답 검수, 군집을 고려한 불확실성을 함께 관리한다. 아직 확보·검수된 2,000문항이 있다는 뜻은 아니다. 세부 규격과 A/B/C 준비 지시는 [PUBLIC_BENCHMARK_PROTOCOL.md](PUBLIC_BENCHMARK_PROTOCOL.md)를 따른다.
- BENCHMARK-RESERVATION-001: 실행 도구 준비와 별개로 시험 예약 문서 확보를 우선한다. B는 전체 정제 완료를 기다리지 않고 `reports/coordination/benchmark-source-inventory.json`에 확인 가능한 문서계열·업무군·사용권·원문 경로·학습 포함 여부를 먼저 인계한다. 확보/후보/차단/unknown을 구분하고, 총괄이 예약·독립 문항 제작·검수 단계로 연결한다.
- RESERVATION-001: 총괄이 `reports/coordination/benchmark-reserve-001.jsonl`에 354기관의 규정1,000계열(8업무군각125)을 잠정 예약했다. 현재 모두 목록 단계이며 원문/사용권/학습미포함 미입증, 최종시험 적합0이다. 해당 계열·개정본·첨부의 향후 학습 제외와 B-003 원문 확보를 지시했다. 원본 예약목록은 총괄 소유·불변이고, 후속확보 상태는 별도로 기록한다. C-005 집계수정은 총괄 재현으로 확인해 채택했고 평가도구 확장은 종료했다. C-006은 기존 QA 검증 완료·내구성 저장·GPU 정지 작업이다.

### 수집 속도 (COLLECTION-SPEED-001)

사용자는 초당 1요청의 수집 지연을 지적했다. 국회 수집기의 기본 --delay=1.0은 임시 보수적 기준이지 모든 출처의 영구 상한이 아니다. 공식 대량 제공 경로와 요청 정책을 먼저 확인하고, 서로 다른 출처 및 AWS 후처리는 독립적으로 병행한다. 동일 호스트 요청은 모든 작업자 합산으로 제한하며 제한 우회용 IP/계정 분산은 하지 않는다. 명시된 제한을 지키고, 제한 미명시 시 작은 단계 증가 관측으로 상한을 정한다. 429/Retry-After/서버 오류·지연 악화에 따라 감속한다. 실제 요청 수·응답 시간·정제/S3 시간을 구분해 처리량과 ETA를 보고하며 1요청=1문서로 가정하지 않는다. 진행 중 상태를 덮어쓰지 않고 안전한 재개 경계에서 변경한다. 이 지시는 B-001의 고정 1초 제한 제안보다 우선한다.

## 최초 지시: 기존 작업 현황 제출

각 세션은 진행 중인 학습을 임의로 취소하거나 새 대규모 학습을 추가하지 않는다. 현재 작업을 안전한 보고 지점까지 진행하고 다음을 보고한다.

- 세션 ID, 현재 목표, 진행/완료/차단 상태
- 수정 중인 파일, 소유한 실행·출력 경로
- 실행 중인 학습의 작업 ID, 체크포인트, 데이터·설정 경로, 진행 상태
- 완료한 결과 보고서 및 원본 응답 경로
- 다음에 하려던 작업과 의존성

총괄이 실제 작업 현황을 확인한 후 아래 역할을 배정했다. 기존 세션 세 개를 유지하며 독립 평가·통합 판정은 총괄이 맡는다.

| 역할 | 세션 ID | 현재 담당 |
|---|---|---|
| A | 01a18739-bcc6-77fc-b2a0-14d216f1becb | 모델·사전학습 및 clean → tokens |
| B | 01a18644-74cb-75c1-8098-96d4f5c0e5fe | 원문 수집·정제 및 raw → clean |
| C | 01a17c28-d03e-753b-8c91-fb508aeaa80c | QA·설명 데이터 및 기존 GPU 작업 |

현재 GPU i-01e894092261d7f9a의 작업 소유자는 C다. A/B는 해당 인스턴스를 중단·재부팅·변경하거나 작업을 추가하지 않는다. C는 기존 작업 상태 및 완료 후 저장 검증·종료 계획을 보고한다. 사용자 승인된 수집 4종의 범위는 유지하며 파일럿 검증 후 단계적으로 확대한다.

첫 감독 작업 ID는 A-001, B-001, C-001이다. 각 세션은 `reports/coordination/A-001.md`, `B-001.md`, `C-001.md`에 완료 보고를 작성하고, 마지막 줄에 각각 `SUPERVISION_REPORT_READY A-001`, `SUPERVISION_REPORT_READY B-001`, `SUPERVISION_REPORT_READY C-001`을 기록한다. 차단 보고도 산출물로 인정하되 상태와 누락된 근거를 명확히 적는다.

## 역할별 첫 작업

### A: 모델·사전학습

소유 범위: 합의한 모델 설정 및 학습 코드, 해당 실행 전용 출력 경로.
첫 산출물: 91M 기준 체크포인트와 350M 후보의 비교 실험 계획.
비교표에 파라미터 수, 구조, 토크나이저, 문맥 길이, 데이터 버전, 학습 토큰 수, 초기화, seed, optimizer, 학습률, 평가·디코딩 조건을 기록한다.
현재 korean-350m 설정은 크기 외 GQA와 QK-norm도 달라 순수 크기 효과 실험이 아니다. 변경을 명시하고 가설과 검증 방식을 구분한다.
작은 검증 학습의 중단·확대 조건을 먼저 제시한다. 모델 크기가 유일한 원인이라고 단정하지 않는다.

### B: 원문 수집·정제

소유 범위: scripts/collect_fineweb2_ko.py, 해당 테스트, scripts/collect_assembly_minutes.py 및 원문 수집·정제 경로.
첫 산출물: 진행 중인 파일럿 결과, 원문 출처·사용권·개인정보 처리·중복 제거·문서 단위 분할 및 clean 행 스키마.
A의 prepare_fineweb2_ko.py와 중복된 다운로드·정제 경계를 비교하고 단일 raw → clean → tokens 계약을 제시한다. 총괄 검토 전 상대 파일을 삭제하지 않는다.
사용자가 승인한 FineWeb-2, 국회 회의록, 공공기관·지방공기업, PRISM·정책브리핑·지자체 수집 범위를 축소하지 않는다. 무조건 전량 학습 투입하는 대신 출처별 수집·사용 적합성을 검증한다.
최종 비공개 평가 문서·정답을 학습 데이터로 전환하지 않는다.

### C: QA·설명 데이터 및 GPU 작업

소유 범위: scripts/build_teacher_qa.py, 합의한 QA 조립 코드·데이터, 기존 teacher GPU 작업.
첫 산출물: 기존 GPU 작업의 실제 진행 증거, 생성·검증·저장 상태, QA 표본의 정답·근거 정합성과 설명 과제 구성 부족분.
우선 과제: 질문 변경, 수치·조건 변경, 예외, 표, 두 근거 결합, 근거 기반 설명.
원문 복사 정답과 공개 모델이 생성한 답변을 구분한다. 외부 가중치 미사용과 외부 모델을 통한 데이터 초안 작성은 다른 정책이며 기존 승인 범위를 유지한다.
완료 전 새 SFT를 시작하지 않는다. 데이터 생성 성공을 모델 성능 개선으로 간주하지 않는다.

### 총괄: 독립 평가·통합 판정

현재 평가와 서비스 체크포인트의 대응, 독해·설명·정답률 규격, 개선·회귀 증거를 검토한다.
생성형 모델과 추출 헤드, 엄격 정답과 정답 언급, 근거 제공 독해와 검색 포함 서비스 성능을 분리한다.
반복 사용한 개발 평가와 최종 비공개 평가를 분리한다. 학습 담당 세션에 최종 평가 정답을 전달하지 않는다.
공유 배포 포인터·README 성능 수정은 총괄 검토 후 단일 담당자에게 명시적으로 배정한다. 현재는 변경하지 않는다.

## 공통 평가와 채택 규칙

- 독해: 같은 문서의 서로 다른 질문, 수치·조건 변경, 표, 다중 근거별 성능.
- 설명: 결론 정확성, 근거의 뒷받침, 조건·예외 누락, 근거 없는 추가 주장. 길이나 유창함만으로 합격시키지 않는다.
- 정답: 답 있음 정답률, 답 있는데 보류, 답 없는데 답함, 출처 정확성을 별도 집계한다.
- 학습 loss 감소, 실행 완료, 근거에 있는 문자열 출력만으로 성능 개선을 선언하지 않는다.
- 같은 문항에서 개선·악화 사례와 불확실성을 함께 보고한다. 적은 표본의 점수나 AI 검토를 독립 사람 검증처럼 표시하지 않는다.
- 채택 수치 기준은 실험 전에 총괄이 기준선에 맞춰 확정한다. 결과를 본 뒤 합격선을 바꾸지 않는다.
- 배포 전 평가한 체크포인트와 서비스 체크포인트가 같은지 확인하고 실제 문서 질의·설명 요청을 검증한다.

## 충돌 방지

- 파일 소유권이 겹치면 편집 전에 총괄에 보고한다. 타 세션의 미완료 변경을 되돌리거나 함께 커밋하지 않는다.
- 실행·데이터·보고서는 고유 경로에 기록하고 기존 결과를 덮어쓰지 않는다.
- 기존 학습과 GPU 자원 사용을 확인한 후 새 실행을 시작한다.
- 배포 모델 교체, 파괴적 정리, 새로운 유료 자원 생성은 기존 사용자 승인 범위를 넘어 임의로 실행하지 않는다.

## 완료 보고 규격

각 작업 완료 시 아래 항목을 보고하고 다음 큰 실험은 총괄 판단을 기다린다. 다른 세션에서 요청된 독립적 검증은 소유권과 자원 충돌이 없을 때 수행할 수 있다.

1. 세션 ID / 역할 / 작업 ID / 상태
2. 가설 및 실제 변경 변수
3. 변경 파일과 소유 범위, 해당되는 경우 커밋
4. 데이터 버전·설정·체크포인트 및 재현 명령
5. 실제 실행한 검증과 원본 응답·보고서 경로
6. 같은 조건의 기준선 대비 결과, 개선·악화 사례
7. 해석의 한계, 미해결 문제와 차단 사항
8. 제안하는 다음 작업

총괄 회신은 `채택 / 추가 검증 / 기각 / 차단` 중 하나와 근거, 다음 작업 범위, 완료 기준을 명시한다. 보고서를 저장한 사실만으로 총괄에 알림이 전달되었다고 간주하지 않는다.
