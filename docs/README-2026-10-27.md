# trid — 직접 학습하는 초소형 한국어 모델

**기존 모델의 가중치를 사용하지 않고 처음부터 학습하는 초소형 언어모델 프로젝트입니다.** Transformer를 직접 구현했고 토크나이저도 자체 학습 데이터로 만들었습니다. Qwen·Llama 등의 가중치를 내려받거나 이름만 바꾸지 않았습니다. PyTorch·Tokenizers·Safetensors는 연산·토큰화·저장에 사용합니다.

**개발 목표는 한국어 전용입니다.** 한국어 기관 문서를 읽고 한국어 질문·후속 대화에 답하는 능력에 집중합니다. 한국어 문서 안의 숫자·단위·기관 약어·제품명은 보존합니다. 학습과 평가의 구체적인 기준은 [한국어 전용 개발 기준](KOREAN.md)에 정리했습니다. 이는 현재 성능을 보장하는 명칭이 아닙니다.

현재는 **자체 사전학습과 짧은 한국어 대화 학습을 진행한 실험 모델**입니다. 인사·자기소개·감사·일상 질문을 중심으로 학습했으며 표현이 달라지면 엉뚱한 답을 할 수 있습니다. 회사 지식을 습득한 제품이 아닙니다.

[모델 카드](MODEL_CARD.md) · [대화 학습 기록](DIALOGUE.md) · [기초 사전학습](PRETRAINING.md) · [공공기관·기업 시연 실험](SHOWCASE.md)

2026-10-27 한국어 개선 실험: 누적 3천만 토큰 기초 사전학습과 1,200단계 독해·대화 학습을 완료했습니다. 기초 전체 검증 손실은 5.405 → 4.119로 개선됐지만, 새 대화 후보는 고정 문서 대화에서 4/40 → 1/40로 퇴보해 **기본 모델로 채택하지 않았습니다.** 자료·코드·실제 출력과 실패 분석은 [한국어 개선 실행 기록](KOREAN_RUN.md)에 있습니다.

추가로 **대화를 제외한 문서 독해 전용 학습 1,200단계**를 완료했습니다. 동일 내부 검증의 답 있음 정답은 0/135 → 2/135, 잘못된 보류는 116/135 → 90/135였지만 답 없음 처리도 퇴보해 기본 모델로 채택하지 않았습니다. 별도 실행법과 결과는 [독해 분리 실험](KOREAN_READING.md)을 참고하세요.

후속으로 **정답 시작·끝 구간 추출 모델**도 1,200단계 학습했습니다. 동일 질문의 답 있음 정답은 2/135 → 11/135로 늘었지만, 답 없음 처리는 47/62 → 0/62로 무너져 전체 성능은 퇴보했습니다. 기존 기본 모델을 유지하며, 별도 확인 방법과 한계는 [구간 추출 실험](KOREAN_SPAN.md)에 기록했습니다.

추가로 **짧은 문서 구간 선택과 답 존재 여부를 별도 모델로 학습**했습니다. 학습과 구분한 좁은 가상 문서 시험은 104/600 → 358/600으로 개선됐지만, 기존 넓은 독해는 5/197이고 없는 기관명 처리도 실패했습니다. 기본 모델은 유지합니다. 두 모델 합계 약 3,474만 파라미터이며 [분리 학습 기록과 실행법](KOREAN_SHORT.md)에 상세 결과가 있습니다.

최근 **항목 대조 학습·한글 문자 특징·추론 연산 최적화**를 진행했습니다. 문서 독해 전용 후보 `runs/trid-korean-short-v3-hangul`은 개발 회귀 998/1,120, 새 합성 진단 75/96입니다. 해외 비용 구분·부서명 추출은 개선됐지만 새 표현의 기관명 부재는 0/12로 실패해 실무 배포용으로 채택하지 않았습니다. 코드 검사 46개 통과. [최신 학습 결과와 실행법](KOREAN_MODEL_OPTIMIZATION.md)에 같은 시험의 비교, 한계와 실제 속도를 기록했습니다.

기관 규정 질의응답용 별도 모델 `runs/trid-grounded-v2`도 학습했습니다. 기존 가상 문서 평가에서 생성 정답은 18/24로 개선됐지만, 새로운 질문·문서 표현·답의 값을 적용한 480문항은 10개만 맞혔습니다. 자료 부족 처리는 3/3에서 1/3로 퇴보했습니다. 고객 시연 준비 기준을 통과하지 못했으며, 일반 대화 모델과 구분되는 실험입니다.

기관 규정 테스트는 **`trid-institution.command`를 더블클릭**하세요. 모델과 선택 문서를 표시하는 전용 입력창입니다. 기본 문서는 출장비(T01)이며 `/sources`와 `/source I01`로 다른 자료를 선택합니다. `trid.command`와 터미널의 `trid chat`은 1번 기관 규정, 2번 일반 대화 중 선택하는 화면을 엽니다.

기관 생성 모드도 최근 질문과 실제 모델 답을 문맥 한도 안에서 전달합니다. `/reset` 또는 자료 변경 시 이력을 비우며 파일에는 저장하지 않습니다. 대화 이력을 전달해도 기관명을 금액으로 답하거나 이전 오답을 정정하지 못하는 문제가 남아 있습니다. T01은 특정 공공기관의 규정이 아닌 가상 시연 자료입니다.

## 바로 실행

Finder에서 `trid.command`를 더블클릭하거나 터미널에서 실행합니다.

```sh
cd '/Users/eomgyuhyeon/사업/trid'
.venv/bin/trid chat
```

터미널에서는 모드 선택 화면이 표시됩니다. 선택을 생략하려면 `.venv/bin/trid chat --mode institution` 또는 `.venv/bin/trid chat --mode dialogue`로 실행하세요. 일반 대화는 기존 `trid-v0.2`이며 이번 기관 규정 추가 학습으로 개선됐다는 의미가 아닙니다. 파이프 입력처럼 대화형 터미널이 아니면 기존 호환성을 위해 일반 대화로 실행하므로 `--mode`를 명시하세요.

아래 제어 명령은 일반 대화 모드 기준입니다.

- `/example`: 인사 입력
- `/reset`: 이전 대화 초기화
- `/exit`: 종료
- `/help`: 입력 도움말 (`/ exit`도 종료로 처리)

`.venv/bin/...` 같은 터미널 명령은 `/exit`로 채팅을 종료한 뒤 쉘 프롬프트에서 실행하세요. 명령을 채팅창에 붙여 넣으면 안내를 표시하며, 실행하거나 모델에 전달하지 않습니다.

짧은 이전 대화를 입력에 포함합니다. 입력과 출력 합계 256토큰을 넘으면 오래된 대화부터 제외하고 알림을 표시합니다. 대화 기록은 파일로 저장하지 않으며 대화 중 자동 학습도 하지 않습니다. 첫 실행은 모델 로딩·GPU 준비 때문에 후속 요청보다 느릴 수 있습니다.

```sh
.venv/bin/trid ask '안녕'
.venv/bin/trid ask '네 이름은 뭐야?'
```

`ask`는 매번 독립적인 질문입니다. `chat`과 `ask`의 기본 모델은 `active-model.json`에 지정합니다. 이 파일이 없으면 과거 가상 업무 모델 `runs/trid-v0.1`을 사용합니다. 실행 시 실제 모델 폴더를 표시합니다.

일반 대화와 기본 기관 규정 모델의 답변은 모델이 다음 토큰을 순서대로 생성합니다. 정답 조회, 외부 LLM 호출, 반복 억제나 응답 대체 후처리는 사용하지 않습니다. 별도 `trid-reader-v1` 실험은 학습한 원문 구간 선택 방식이며, 평가 미달로 기본 모델에 연결하지 않았습니다.

## 구현

| 항목 | 한국어 대화 학습 모델 |
|---|---|
| 구조 | Decoder-only Transformer, 8층, hidden 384, attention head 6 |
| FFN | SwiGLU, 중간 차원 1,024 |
| 위치·정규화 | RoPE, RMSNorm |
| 어휘 | 자체 Wikipedia 학습 split에서 만든 byte-level BPE, 8,192개 |
| 초기 가중치 | 무작위; 입력·출력 임베딩 공유 |
| 학습 | 문서 다음 토큰 예측 → 답변 구간 지도학습 + 질문 유형 보조 손실 |
| 문맥 | 입력과 출력 합계 256토큰 |
| 실행 | macOS MPS 또는 CPU, KV cache |
| 저장 | Safetensors 가중치와 JSON 설정·토크나이저 |

언어모델 본체는 **17,308,032 파라미터**, FP32 가중치 약 **69.24MB**입니다. 질문 유형 구분용 학습 보조 헤드는 약 2만 파라미터이며 실제 답변 생성에는 사용하지 않습니다. 실행 메모리에는 프레임워크·중간 연산 등이 추가됩니다.

널리 쓰이는 Transformer 구성요소를 조합한 자체 구현입니다. 새로운 학술적 아키텍처를 발명했다는 의미는 아닙니다.

## 추가 학습

```sh
uv sync --frozen --extra corpus --python 3.12
.venv/bin/trid train --init-run runs/trid-dialogue-v3 \
  --data data/dialogue-v4 --output runs/dialogue-new \
  --steps 2400 --batch-size 24 --lr 0.0001 \
  --eval-every 200 --validation-limit 0 --intent-weight 0.2
```

데이터 생성·학습 계보·평가 방법은 [DIALOGUE.md](DIALOGUE.md)에 기록되어 있습니다. `train`은 `--init-run`이 없을 때 무작위로 시작하고, 지정하면 자체 로컬 모델의 가중치를 이어 받습니다. 대화 학습의 옵티마이저는 복원하지 않습니다. 문서 사전학습의 `pretrain --resume`은 옵티마이저·난수 상태까지 재개합니다. 기존 결과 경로를 덮어쓰지 않습니다.

질문·답변 JSONL 형식:

```json
{"prompt":"내 이름이 뭐야?","answer":"민수라고 말씀하셨어요.","history":[{"user":"나는 민수야.","assistant":"반가워요, 민수님."}],"task":"name_memory"}
```

`history`는 생략할 수 있습니다. 문맥을 초과하는 학습 행은 조용히 자르지 않고 오류를 냅니다. 회사 자료를 자동 수집하지 않습니다. 실제 업무 데이터는 사용 권한이 있는 자료를 별도로 준비해야 합니다.

## 보안과 현재 범위

- 학습·추론 중 외부 API 호출, 가중치 다운로드, 원격 코드 실행, 외부 서버 업로드가 없습니다. 패키지 설치 및 명시적인 공개 말뭉치 다운로드는 네트워크를 사용합니다.
- 일반 CLI는 네트워크 서버를 열지 않으며 대화 로그를 저장하지 않습니다. 별도 PDF 실험 화면은 `127.0.0.1`에만 서버를 엽니다. 외부 연결을 받지 않으며 문서·질문은 앱 메모리에서 처리합니다.
- 평가 스크립트와 `evaluate`는 지정한 로컬 보고서에 질문·정답·출력을 저장합니다.
- CLI가 새로 만드는 파일은 소유자 전용 권한을 사용합니다. 이미 존재하는 파일의 권한을 자동 변경하지는 않습니다.
- 운영체제 수준 네트워크 차단, 암호화, 기업별 접근 통제나 보안 인증을 제공하지 않습니다. 모델의 말은 보안 경계가 아닙니다.
- 학습 가중치가 학습 내용을 기억할 수 있으므로 민감한 자료로 학습한 모델도 기밀로 관리해야 합니다.

## Raspberry Pi 목표

CPU 실행 경로는 있지만 **Raspberry Pi 실측은 아직 없습니다.** M5 응답 속도를 Pi 성능으로 해석하면 안 됩니다. 현재 FP32 가중치이며 양자화하지 않았습니다. 실제 Pi의 메모리·첫 응답·전체 응답 시간을 확인한 뒤 실행 엔진과 양자화를 조정해야 합니다.
