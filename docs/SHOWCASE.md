# 공공기관·기업 대상 trid 시연

## 첫 시연의 목적

**기관 내부 규정과 업무 매뉴얼을 근거로 답하는 로컬 AI**를 첫 적용 사례로 삼습니다. 핵심은 답변 정확도, 근거 확인, 자료 부족·충돌 처리, 작은 모델의 로컬 실행입니다. 실제 기관의 규정·법령·보안 인증을 구현했다는 의미는 아닙니다.

모든 규정·금액·부서·번호는 시연용으로 작성한 가상 설정입니다. 실제 공공기관이나 고객사의 문서를 수집하거나 학습하지 않았습니다. 사전학습 가중치는 자체 무작위 초기화에서 시작한 trid 계보를 이어 받으며, 외부 모델이나 Jev API를 사용하지 않습니다.

## 시연 범위

| 분야 | 가상 문서 ID | 예시 질문 |
|---|---|---|
| 출장비 | T01 | 국내 출장 식비는 하루 얼마야? |
| 구매 승인 | P01 | 정확히 50만원인 물품의 승인자는 누구야? |
| 휴가 신청 | L01 | 연차 신청은 어떤 시스템으로 접수해? |
| 장비 문의 | I01 | 업무용 노트북이 고장 났어. 어디에 신고하지? |
| 기록 관리 | R01 | 회의록은 몇 년 동안 보관해? |
| 방문 예약 | V01 | 토요일에도 방문할 수 있어? |

자료: `data/institution-demo-v1/documents.json`.

현재 실험은 **운영자가 관련 문서를 직접 선택해 모델에 제공**합니다. 자동 문서 검색이나 권한에 따른 접근 통제는 구현하지 않았습니다. 화면에 제공 자료를 표시하는 것은 모델 답변이 그 자료와 일치한다는 검증을 대신하지 않습니다.

## 학습과 평가 분리

- 학습: `data/institution-training-v1/train.jsonl` 12,057행. 가상 규정의 금액·부서·기간과 질문 표현을 바꾸며, 짧은 값 생성과 A/B/C 선택을 함께 학습합니다.
- 검증: 899행 중 고정 256행을 체크포인트 선택에 사용합니다. 학습과 다른 질문 표현을 쓰지만 같은 주제·답변 후보·템플릿 계열을 공유합니다.
- 시연 평가: `data/institution-demo-v1/eval.jsonl` 24문항. 정규화한 질문 문자열을 학습·검증에서 제외했습니다. 생성 방식과 선택 방식에 동일한 근거를 제공합니다.
- 선택 방식에서는 각 문항의 선택지 순서를 6가지 모두 바꿔, 특정 위치만 고르는지 확인합니다. 출력 확률은 보정되지 않았으며 실제 정답률로 표시하지 않습니다.
- 같은 질문에서 근거의 식비 또는 보관 기간만 바꾸는 2쌍을 포함합니다. 재학습 없이 새 입력을 읽는지 확인하기 위한 시험입니다.

개발자가 기준 모델의 평가 결과를 본 뒤 학습 자료를 설계했으므로, 완전히 독립적인 최종 성능 인증이 아닙니다. 이 합성 자료에서 잘 맞는다고 실제 기관 문서에서 같은 정확도가 나온다고 주장하지 않습니다. 다음 단계에서 별도의 실제 문서·질문 평가가 필요합니다.

## 재현

```sh
cd '/Users/eomgyuhyeon/사업/trid'

# 학습 데이터 생성: 해당 출력 폴더가 아직 없을 때만 실행
.venv/bin/python scripts/prepare_institution_training.py

# 기존 폴더를 덮어쓰지 않고 새 실험 경로 지정
.venv/bin/trid train --data data/institution-training-v1 \
  --output runs/institution-new --init-run runs/trid-v0.2 \
  --steps 1200 --batch-size 24 --lr 0.00015 \
  --eval-every 100 --validation-limit 256

.venv/bin/python scripts/evaluate_institution_demo.py \
  --run runs/institution-new --output reports/institution-new.json
```

평가 스크립트는 정답을 응답으로 대체하지 않습니다. 생성 방식은 실제 모델 출력을 저장하며, 선택 방식은 모델의 다음 토큰 점수를 A/B/C로 제한합니다. 선택 결과의 문자열 표시는 선택한 항목을 보여주는 일반 코드입니다. 이를 자유로운 문장 생성이나 Jev 구현으로 설명하지 않습니다.

## 직접 실행

Finder에서 `trid-institution.command`를 더블클릭하면 기관 규정 전용 입력창을 엽니다. 처음에는 출장비 문서 T01이 선택됩니다. `/sources`로 목록을 보고 `/source I01`처럼 자료를 바꿀 수 있습니다. 생성 모드에서는 문맥 한도 안에서 이전 질문과 실제 모델 답을 전달하며, 자료를 바꾸거나 `/reset`을 실행하면 이력을 초기화합니다. 대화는 메모리에서만 유지합니다. 구간 선택 실험은 여전히 질문별 독립 실행입니다. 화면에 모델 경로와 선택 자료를 표시합니다.

`trid.command`와 대화형 터미널의 `trid chat`에서는 1번 기관 규정, 2번 일반 대화 모드를 선택합니다. 일반 대화 모드는 기관 규정을 입력에 제공하지 않습니다. 바로 기관 모드로 열려면 `.venv/bin/trid chat --mode institution`을 실행하세요.

```sh
.venv/bin/python scripts/institution_demo.py --chat --source T01

.venv/bin/python scripts/institution_demo.py --source T01 -- '국내 출장 식비는 하루 얼마야?'
.venv/bin/python scripts/institution_demo.py --source I01 -- '업무용 노트북이 고장 났어. 어디에 신고하지?'
.venv/bin/python scripts/institution_demo.py --source V01 -- '토요일에도 방문할 수 있어?'

# 후보를 직접 제시하는 별도 선택 방식
.venv/bin/python scripts/institution_demo.py --source T01 \
  --run runs/trid-institution-v1 --choices '3만원' '5만원' '자료없음' -- '국내 출장 식비는 하루 얼마야?'
```

현재 기관 모드 모델은 `active-institution-model.json`이 지정하는 `runs/trid-grounded-v2`입니다. 일반 대화의 `active-model.json`은 기존 `trid-v0.2`를 유지합니다. 새 자료를 시험하려면 문서 JSON을 복사하고 `--documents 복사본경로`를 지정하세요. 원본 평가 자료와 보고서를 덮어쓰지 않습니다.

## 시연 준비 판단

다음은 내부 개발 목표이며, 이미 달성한 성능이나 공공기관 납품 기준이 아닙니다.

- 24문항 중 적어도 22문항에서 근거에 맞는 답변.
- 정보 부족 3문항과 충돌 2문항 모두 임의 확정 없이 처리.
- 근거만 바꾼 2쌍 모두 답변도 올바르게 변경.
- 선택 방식은 위치 변경에도 정답이 유지되는지 함께 공개.
- 사람 검토를 거친 별도 실제 문서 평가를 통과한 뒤 실무 성능을 설명.

문서 접근 권한은 검색 전에 프로그램이 검사해야 하며 모델의 거절 문구로 대신할 수 없습니다. 금액 계산·날짜 비교·승인 조건처럼 정확한 계산이 필요한 실무 절차는 규칙 코드와 결합해 별도로 검증해야 합니다. 현재 숫자 조건 문제는 모델의 한계를 알아보는 가상 시험입니다.

M5에서 로컬 실행한 결과와 Raspberry Pi 성능은 구분합니다. Pi 실측, 운영체제 수준 망 차단, 암호화, 기관별 계정·권한·감사 기록은 아직 검증하거나 구현하지 않았습니다.

추가로 합성 검증 자료의 생성 문제 100개를 고정 시드 920으로 추출해 확인했습니다. 정답은 60/100, 단순 값 추출은 20/49였습니다. 이 검증 split은 체크포인트 선택에도 쓰였으므로 독립적인 성능 검증이 아닙니다. 학습과 유사한 문장에서도 값 추출이 약하고, 시연 문서의 다른 표현에서는 더 취약한 결과입니다. 낮아진 토큰 손실을 업무 정답률로 해석하지 않습니다.

보고서:

## 후속 개발: 생성 v2와 원문 구간 선택 실험

사용자의 실제 실행 로그를 기준으로 입력 처리와 문서 읽기 학습을 개선했습니다. `/ exit`를 종료로 인식하며, 잘못된 슬래시 명령·방향키 제어 문자·붙여 넣은 `.venv/bin/...` 명령은 모델에 보내지 않습니다. 쉘 명령을 자동 실행하지 않고 채팅 종료 후 실행하도록 안내합니다. 터미널의 `trid chat`에는 기관 규정/일반 대화 모드 선택 화면을 추가했습니다.

`data/grounded-v2`는 기관 문서 학습 14,000행과 기존 자체 대화 자료 재사용 1,855행, 검증 600행으로 구성했습니다. 문서 표현 5종과 질문 표현 6종을 학습에 사용하고, 검증·평가에는 별도 표현을 사용했습니다. 새 평가 480문항은 240쌍이며 각 쌍에서 질문을 유지하고 문서의 답만 바꿉니다. 이번 추가 학습 자료에 없던 수치 범위·전화번호·부서·시스템 이름을 사용합니다. 승인 직책의 후보는 겹칩니다. 일반 사전학습 전체에서 해당 단어나 숫자가 등장하지 않았다는 뜻은 아닙니다.

학습·검증·평가의 전체 입력 문자열은 겹치지 않습니다. 다만 주제와 개발자가 같고 평가 템플릿을 직접 작성했으므로, 독립 평가나 실제 기관 성능을 대표하지 않습니다. 기존 24문항은 이미 확인한 개발 회귀 평가입니다.

| 생성/추출 정답 | 기존 기관 생성 v1 | 개선 생성 v2 | 구간 선택 reader v1 |
|---|---:|---:|---:|
| 기존 24문항 | 8/24 | 18/24 | 17/24 |
| 기존 문항 중 실제 값 답변 | 3/19 | 15/19 | 16/19 |
| 기존 자료 없음 3문항 | 3/3 | 1/3 | 0/3 |
| 기존 규정 충돌 2문항 | 2/2 | 2/2 | 1/2 |
| 새 표현·문서 형식·값 480문항 | 0/480 | 10/480 | 0/480 |
| 새 값 변경 240쌍 모두 정답 | 0/240 | 0/240 | 0/240 |

모두 동일한 근거를 직접 제공하고 공백·끝 문장부호만 정규화한 정확 일치입니다. 새 평가의 오답을 올바른 값으로 대체하지 않았습니다. reader는 잘못된 부서나 불완전한 문자열 구간을 선택했습니다. **생성 v2도 고객 시연 준비 기준을 통과하지 못했으며, 정보 부족 처리의 퇴보가 있습니다.** 익숙한 문서에서 개선된 개발용 모델로만 기관 모드에 연결했습니다. reader는 기본 실행에 연결하지 않았습니다. 일반 대화 모델은 변경하지 않았습니다.

실제로 `국내 출장 식비는 하루에 보통 얼마야?`에 T01 문서를 제공했을 때 생성 v2의 출력은 `3만원`입니다. 이는 가상 문서의 값이며 일반적인 출장비 기준을 주장하는 답이 아닙니다.

생성 v2는 3,600단계를 계획했으나 학습 손실과 검증 손실의 격차가 커져 3,000단계 체크포인트 이후 조기 종료했습니다. 최저 검증 손실의 1,400단계 가중치를 보존했습니다. 마지막 저장 지점까지 학습 시간은 693.2초, 가중치 크기는 69,237,544바이트입니다. reader는 이 자체 가중치에 문자 구간 선택·자료 부족·충돌 판정 헤드를 붙여 1,400단계를 학습했습니다. 검증 기준 300단계 모델을 선택했으며 17,428,995 파라미터, 69,722,508바이트, 학습 343.73초입니다. 출력은 선택한 원문 구간 또는 판정 클래스이며 자유 문장 생성이나 Jev 구현이 아닙니다.

보고서:

- `reports/grounded-v2-baseline.json`: 새 480문항의 기존 모델 결과.
- `reports/grounded-v2-generation.json`, `reports/grounded-v2-legacy.json`: 생성 v2의 새 평가·기존 평가.
- `reports/reader-v1-fresh.json`, `reports/reader-v1-legacy.json`: 구간 선택 모델의 새 평가·기존 평가.

재현 명령은 아래와 같습니다. 기존 결과 폴더나 보고서를 덮어쓰지 않도록 새 경로를 지정하세요.

```sh
.venv/bin/trid train --data data/grounded-v2 --init-run runs/trid-institution-v1 \
  --output runs/grounded-new --steps 3600 --batch-size 24 --lr 0.0002 \
  --eval-every 200 --validation-limit 256
.venv/bin/python scripts/train_reader.py --data data/grounded-v2 \
  --init-run runs/trid-grounded-v2 --output runs/reader-new --steps 1400
.venv/bin/python scripts/evaluate_grounded.py --run runs/grounded-new \
  --data data/grounded-v2/test.jsonl --output reports/grounded-new.json
```

위 생성 학습 명령은 3,600단계를 모두 수행합니다. 이번 수동 조기 종료 시점까지 자동 재현하는 명령은 아닙니다. 각 실험의 선택된 실제 가중치 해시는 평가 보고서에 기록되어 있습니다.

코드 검사 18개가 통과했으며, 이는 모델의 업무 정확도를 보증하지 않습니다. 문서 구간 학습에서는 학습 정답을 질문 뒤에 덧붙이거나 정답 전용 후보 목록을 넣지 않습니다. 후보 영역은 추론 시 주어진 문서 전체이며, 테스트에서 학습용 정답 유무에 따라 입력·후보 마스크가 달라지지 않는 것을 확인했습니다. 새 문서 표현에 대한 이해, 정확한 승인 조건 처리, 정보 부족 구분은 여전히 해결해야 할 과제입니다.

## 사용자 후속 질문 회귀: 기관명과 이전 오답 설명

`출장비가 얼마야? → 어느 기관 규정인데? → 공공기관 이름이 뭔데? → 10일이 뭔말이야? → 뭐가 10만원이야` 대화를 그대로 회귀 평가에 추가했습니다. T01은 실제 공공기관의 문서가 아니라 개발자가 만든 가상 시연 규정이며, 특정 기관명은 지정하지 않았습니다. 식비 하루 3만원을 출장비 총액처럼 답해서도 안 됩니다.

기존 기관 입력창이 이전 대화를 모델에 전달하지 않는 것을 확인해, 생성 모드에 실제 이전 질문·답변 전달과 `/reset`을 추가했습니다. 문맥 한도 때문에 제외한 이력은 화면에 표시하며, 자료를 바꾸면 이전 문서에 관한 대화를 제거합니다. 정답을 이전 답으로 넣는 방식은 사용하지 않습니다.

동일한 가중치로 독립 질문과 실제 생성 답변을 포함한 연속 대화를 비교했습니다. **기관명·오답 설명 질문 4개는 두 방식 모두 실패했습니다.** 첫 질문의 `3만원`은 식비와 출장비 총액을 구분하지 못한 불충분한 응답입니다. 대화 이력 전달 수정은 입력 경로의 수정이며 모델의 의미 이해가 해결됐다는 주장이 아닙니다. 이번에는 추가 학습이나 모델 교체를 하지 않았습니다.

- `reports/institution-followups-v2.json`: 두 방식의 원문 출력과 실제 전달한 이력.
- `reports/institution-followups-v2-review.json`: 의미 검토 결과.
- `reports/institution-history-smoke.json`: 이력 전달 및 자료 변경·초기화 동작 검사.
- `scripts/probe_institution_followups.py`: 새 출력 경로를 지정해 회귀 평가를 재실행하는 도구.

앞선 18/24는 익숙한 가상 문서의 단일 질문 평가로, 기본 한국어 대화나 자유로운 후속 질문을 이해한다는 근거가 아닙니다. 다음 모델을 판단할 때는 기관명/부서/기간/금액 구분, 모호한 질문의 확인, 정보 부족, 이전 오답 정정을 각각 평가해야 합니다. 이 사용자 회귀 질문은 개발용이며 독립 최종 평가로 재사용하지 않습니다.
