# RELEASE-COMPAT-002: TRID 1.7B 학습 계약과 실서비스 검증 계약 맞추기

- **작성:** A (01a18739)
- **게시:** 15:19 KST(커밋 `10fdd76`, `706a11d`). 이후 TRID-WORKSPACE-001 배포에 통합했다(15:36, `e12ff6c`).
- **비용:** 새 학습·GPU·AWS 지출 없음.

## 1. 원인 진단 (기존 코드로 원시 출력 기록)
- **불일치:** 학습은 `CASE_SYSTEM`(결론·이유·조건·예외를 설명하라는 지시)과 설명문 target으로 했다. 반면 사이트는 값 전용 지시(`SYSTEM`, "값 [Dn]만, 설명 금지")와 64토큰으로 서빙했다. 템플릿과 사고 모드 끔은 같았다.
- **값 지시 서빙 7문항의 결과:**
  - 7건 모두 형식이 불일치했다: `[결과] … [근거] …`, 문장형, 출처 없는 값.
  - 1건(연료)은 64토큰 한도에 걸려 잘렸다.
  - **의미 오류:** 정보가 없는 질문(전화번호)에 문서를 그대로 복사했다. 보류해야 하는 문항이다.
  - 형식 불일치와 의미 오류를 나눠 세면: 형식 7/7, 의미 1/7(보류 실패).
- **학습과 같은 `CASE_SYSTEM`으로 서빙했을 때 (같은 6문항, 512토큰):**
  - 문장형 답을 낸다. 해외 식비, 정산 기한, 국비·지방비는 내용이 맞았다.
  - **의미 오류 1건:** 정보 없는 질문에 근거에 없는 전화번호 `02-3456-7890`을 지어냈다.
  - **반복 출력 3건:** 같은 문장을 반복해 512토큰까지 갔다.

## 2. 설계 선택: 일반 스키마 "원문 인용 + 미검증 해설"
- **서빙 지시:** 버전 설정 `answer_mode: case`로 학습과 같은 `CASE_SYSTEM`을 쓴다. 최대 256토큰, greedy.
- **원문 인용 (검증됨):**
  - 출력을 문장으로 나눈다. 앞머리 태그(`[…]`, `Dn:`)는 떼어 낸다.
  - 검색된 원문 구간에 **글자 그대로** 있는 문장(4자 이상)만 "원문 인용 · 글자 그대로 확인됨"으로 강조한다. 출처(기관·문서·조문)를 함께 붙인다.
  - 길이 한도에서 잘린 마지막 조각은 인용으로 쓰지 않는다.
- **모델 해설 (미검증):**
  - 나머지 문장은 "**모델 해설 · 검증 안 됨 — 원문과 대조하세요**"로 따로 표시한다. 검증된 답으로 올리지 않는다.
  - 검색 원문이나 질문에 없는 숫자가 든 문장은 **숨긴다.** 몇 문장을 숨겼는지는 경고로 표시한다.
  - 숫자가 원문에 있다고 해서 그 문장이 사실이라는 뜻은 아니다. 카드에도 그렇게 적었다.
  - 반복 문장은 하나로 줄이고, 몇 회 생략했는지 표시한다.
- **하지 않은 것:**
  - 숫자나 조문 문자열이 들어 있다는 것만으로 해설을 "검증됨"으로 표시하지 않는다(부정·조건·주체·예외 오류는 걸러지지 않기 때문).
  - 특정 질문이나 모델 전용 특례를 두지 않는다. `[결과]` 같은 태그는 일반 태그 제거 규칙으로만 처리한다.
  - 원본 기준선 버전은 기존 값 계약(`grammar_instructed`)을 그대로 쓴다.
- **테스트:** 3개를 추가했다.
  - 원문 문장만 강조되고 해설은 검증되지 않은 것으로 남는다.
  - 근거 없는 숫자가 든 해설 문장은 숨겨진다.
  - 반복 문장은 하나로 줄어든다.
