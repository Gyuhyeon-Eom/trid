## 3. 정합성과 노출 점검 (실패하면 빌드 중단)

**정합성:**
- 내용 해시를 다시 계산해 검토 기록과 맞췄다.
- 학습 제외(hold) 사례는 0건이다.
- 예약 겹침 문서와 B v3 valid/test 문서는 0건이다.
- 질문과 target이 같은 중복은 0건이다(C-016에서 중복 3쌍을 이미 제외).

**평가 노출 점검:** 다음 평가 쪽 자료에서 문서 전체 id, 안건번호, 질문 앞부분을 검색했다.

**발견 1:** 「국고금 관리법」(`law-go-kr:law:276079`)은 **기존 평가셋 `korean-rag-eval-multihop-v1`의 원천 문서**다(`provenance.json`). 이 법률 제3조·제20조로 만든 조문 사례 7건을 pilot에서 뺐다. 평가셋은 건드리지 않았다.

**발견 2:** `expc:344033`(쓰레기처리장 장려수당)은 C-010 과제 원천 records(개발 측정용)에 들어 있다. pilot에서 뺐다.

**오탐 정정:** 숫자 문서번호만으로 검색하면 해시 문자열 속 숫자와 겹쳐 오탐이 많았다. 그래서 다음 기준을 쓴다.
- 문서 전체 id.

- 질문 앞 40자.
- 데이터셋 번호는 숫자 경계를 지키고 제목도 함께 맞을 때만 노출로 본다.

## 4. 시점 표시

- **공식 해석례와 쉬운 설명:** `as_of_interpretation_date=<해석일자>; current_law_unverified`. 2015년 이후 해석이라도 현행으로 표시하지 않는다.
- **조문:** "시행일 기준, 이후 개정 미확인".
- **표·공공데이터:** "수집 시점 스냅샷, 현행 값 미확인".

## 5. split과 반복 비중 (A 확인 필요)

**split:** 문서 단위로 나눴다(문서 id 해시, pilot_dev 약 15%). 한 문서에서 나온 사례는 같은 split에 들어가므로 쉬운 설명과 원문도 같은 split이다.
- pilot_dev 18건: 경북권 위임전결 표 9, 주차장정보 표준 3, 공식 해석례 5, 쉬운 설명 1.
- 조문 사례 4건은 같은 문서(회계예규)라 모두 train이다. **pilot_dev에는 조문 과제가 없다.**

## 6. A 인계 (`C-017/pilot/`)

| 파일 | sha256 (앞 16자) |
|---|---|
| `pilot.jsonl` (75건; question/context/target, split, split_group, task_type, behavior, source_answer_present, time_label, review, content_sha256) | manifest의 `sha256` 필드 |
| `manifest.json` (기준, 수, 제외 사유, 노출 제외 목록, 입력 sha) | (커밋) |

**A에게 전달하는 조건:**
- `official_answer_extraction`은 정답이 입력에 있는 추출 과제다. 생문서만으로 추론하는 능력의 증거가 아니다.
- 표 사례는 해당 기관의 규정이다. 다른 기관으로 일반화하지 않는다.
- pilot_dev는 실험 내부 확인용이다. 최종 평가가 아니다.
- 이 문서들로 최종 평가 점수를 내지 않는다. 다만 C 목록으로 기존 평가셋을 지우지는 않는다.
- 업샘플링하지 않는다. 결과는 task_type별로 보고한다.
