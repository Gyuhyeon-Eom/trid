## 1. 각주: 원래 구획에 붙여 전달 (우선 1)

### 계약 제안 (`C-015/footnote-contract.md`, B 확인 요청)

- **쓰는 것:** B v3-norm2의 `footnote` 편집만 쓴다. 필드는 `src_start`, `src_end`(원본 v3 offset), `replacement=[각주N]`이다. 다른 정규화 규칙은 쓰지 않는다.
- **원본 대조:** 원본 v3의 sha256과 편집의 `source_sha256`이 다르면 빌드를 중단한다. 원본 offset과 hash는 그대로 유지한다.
- **B 확인 전:** 각주 사례는 A에게 넘기지 않는다.

### 빌더 (`scripts/build_internal_cases.py --footnotes …`)

- **처리 방식:**
  - 원본 v3 글을 질의요지·회답·이유 구획으로 offset 기준으로 나눈다.
  - 구획 안의 각주를 `[각주N]`으로 바꾸고, **그 구획이 인용한 각주 본문만** 구획 끝에 원문 그대로 붙인다.
  - 그래서 질의요지의 전제·정의는 질문에, 이유의 판례 인용은 근거에 남는다.
- **사례를 만들지 않는 경우(검증):**
  - 구획 경계를 넘는 각주.
  - 구획 안에서 표지와 본문이 1:1로 맞지 않음(참조 누락, 번호 중복).
  - 같은 본문이 두 구획에 붙음(정의 반복).
  - 처리 뒤에도 `N)N)`이 남음.

### 회귀 테스트 (`tests/test_build_internal_cases.py`, 5개 OK)

실제 해석례 문장(expc:329517의 전제, expc:333611의 정의)으로 만든 행을 쓴다.
- 전제·정의 각주는 질문 끝에 붙고, 이유의 판례 각주는 질문에 들어가지 않는다.
- 각주 편집이 없으면 각주가 섞인 행은 사례가 되지 않는다.
- 한 구획에서 번호가 겹치면 거부한다.
- 같은 본문이 두 구획에 붙으면 거부한다.
- 경계를 넘는 각주는 거부한다.
