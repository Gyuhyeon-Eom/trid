# HYBRID-RAG-001 — 실제 임베딩, hybrid 검색, 서비스 연결

- **작성:** A (01a18739), 2026-10-30
- **결론:** 로컬 bge-m3 임베딩과 BM25를 결합한 검색을 실서비스에 연결했다(Worker `e90e8468-4fa6-483d-b3c4-d601ae6cb1b7`, 17:53 KST). B의 기존 DRF 스냅샷 신규 5건도 실사이트에서 검색·응답에 쓰인다.
- **S3:** **새 API 수집과 S3 업로드는 0건이다.** B는 새 API 키와 비root writer가 없어 이 작업이 막혀 있다. S3 완료라고 주장하지 않는다.
- **정형 통계:** 스냅샷의 structured_facts가 0건이라 **정형 통계 조회는 아직 실데이터로 검증되지 않았다.** 집계 코드와 테스트만 있다.
- **우선순위:** 사용자 재정렬에 따라 추가 확장은 멈추고 MODEL-REPAIR-001로 넘어간다.

## 1. 자원과 재사용
- **기존 코드 재사용:**
  - `scripts/benchmark_retrieval.py`: sentence-transformers dense + RRF 비교 코드
  - `trid/service/index.py`: kiwi BM25
- **임베딩 모델:** 로컬 HF 캐시의 `BAAI/bge-m3`(MIT)를 쓴다. snapshot `5617a9f6…`, 가중치 sha `b5e0ce34…`.
  - 새 vector DB, OpenSearch, GPU job, 유료 자원은 쓰지 않았다.
  - 저장 방식은 numpy float16 행렬로 정확 코사인 검색을 한다. 101k×1024 크기이며 질의 1건에 약 0.1초 걸린다.
- **맥미니:** `eomgyuhyeon-ui-Macmini.local`이 이 맥북에서 이름 해석되지 않아(SSH 실패) Ollama 상태를 확인하지 못했다. 이전 기록에 운영 서비스가 돌고 있다고 되어 있어 쓰지 않았다.
- **임베딩 실행 위치:**
  - 맥북 MPS(fp16, nice 10, 길이순 배치)로 96,966개 고유 입력을 24분에 임베딩했다.
  - 실행 중에도 실서비스 llama-server는 계속 응답했다.
  - 서비스 질의 임베딩은 CPU에서 한다.

## 2. 구성 (커밋 `5e6d3c7`, `0665b56`)
- **`scripts/build_embeddings.py`, `trid/service/embed.py`:**
  - 입력 문자열 `기관 제목\n구간` 자체의 sha256을 키로 하는 저장소(`runs/embeddings/bge-m3`, 2,048개 단위 shard, 원자적 기록)를 쓴다.
  - **재시작:** 같은 명령으로 이어서 진행한다. v2 재실행 시 "to embed 0"이었고 vectors sha가 같았다.
  - **변경분만 갱신:** v3에서는 102개 입력만 새로 임베딩했다(11초).
  - 색인 폴더에 `dense.f16.npy`와 `dense.json`(model, snapshot, vectors_sha256)을 쓴다.
- **`Workspace.scores` (hybrid):**
  - 점수 = 0.1 × BM25/max + 0.9 × 코사인(질의별 중앙값=0, 최고=1로 재척도) × 권위 가중치.
  - **권위 가중치:** 법령·별표 1.0 / 규정·편람·해석 0.9 / FAQ 0.85 / 민원 게시판 0.7.
  - 기관 필터, 문서명 필터, 기관 되묻기, 이어지는 질문 처리는 그대로 이 점수 위에서 동작한다.
- **공식 기관 목록:**
  - 출처는 `data/corpus-inventory/alio-agencies.json`(ALIO 355개)과 색인의 발행기관이다.
  - 별칭은 일반 규칙으로만 만든다. 제목 접두어 한국·국립·대한을 떼고 3자 이상 남는 경우이며, 두 기관이 겹치는 별칭은 버린다. 예: 부동산원 → 한국부동산원(공기업 준시장형, 주무부처 국토교통부).
  - 목록에 있지만 자료가 없는 기관은 그렇게 안내하고, 다른 기관 자료로 대신 답하지 않는다.
- **근거 적합성 검사 (모델 호출 전):**
  - 최고 코사인이 0.6 이상이어야 한다.
  - 0.7 미만이면 질문 핵심 명사의 idf 질량 40% 이상이 해당 구간에 있어야 한다.
  - 통과하지 못하면 무엇이 없는지 말하고, 무관한 문서는 나열하지 않는다. 되묻기 후보와 "다른 문서" 목록도 통과한 문서만 쓴다.
- **B 스냅샷 반입 (`scripts/build_workspace_index.py --api-snapshot`):**
  - manifest의 파일별 sha256을 검사한다.
  - `rights.restrictions`가 있는 레코드는 제외한다.
  - **source+ID 중복 제거:** law.go.kr의 일련번호(version)가 이미 문서 id이면 건너뛴다.
  - 날짜 종류는 `date_kinds`에 따라 표시한다(발령일자).
  - 발행기관은 행정기관코드 그대로 둔다(ALIO id 아님). `applies_to`는 발행기관과 별도로 보존한다.
- **B search-corpus-v4 검토 메타데이터 (manifest `1c59fb25…`):**
  - 본문, id, hash가 같으므로 다시 임베딩하지 않았다. 질의 단계에서 적용한다.
  - `privacy_review` 2구간은 점수를 0으로 만들어 어떤 순위에도 나오지 않는다. 모델 입력, 응답, 출처 본문 어디에도 쓰이지 않는다.
  - `hold_for_value_use` 87구간은 다음처럼 처리한다:
    - 숫자를 인용하거나 근거로 쓰지 않고, "원문(쪽)에서 직접 확인" 안내를 붙인다.
    - 값만 답하는 버전(v0.1, 기준선)은 이 구간을 아예 읽지 않는다.

## 4. 측정 (A 개발 측정, 독립 평가 아님)

`HYBRID-RAG-001-dev-eval.json`, 목표 문서가 정해진 14문항:

| 검색 | doc@1 | doc@3 | doc@5 | doc@10 |
|---|---|---|---|---|
| 이전 서비스 BM25 | 2 | 3 | 6 | 7 |
| hybrid (현재) | 7 | 9 | 12 | 12 |

- **가중치 결정:** 같은 14문항으로 혼합 비율과 권위 가중치를 골랐다(0.5/0.3/0.2/0.1, RRF 비교). 같은 문항으로 고르고 평가했으므로 과적합 위험이 있다.
- **원인 사례:** BM25는 "식비는"을 kiwi가 `식/비`로 쪼개 핵심어를 잃는다.
- **자료 밖 질문 8개:** 7개가 근거 없음으로 처리됐다. 나머지 1개("사내 동호회 활동비")는 권익위 동호회 질의응답이 통과했다.
