## 1. v0.1 추출 독해기: 답이 있는 질문인데 보류 (C-021 0/5)

진단은 파이프라인 단계별로 했다: 모델 원시 예측 → 문단 선정 → span 위치 검증 → UI.

1. **체크포인트 일치: 정상**
   - 사이트 가중치는 `90ccb60f…`이고 기록과 같다.
   - 같은 가중치로 기관 probe 40문항을 로컬에서 다시 돌렸다(`scripts/evaluate_extractive.py`).
   - 결과: 원시 출력이 기록(`reports/reader-factorial-01-cpt-v1-v2-v4-probe.json`)과 **40/40 동일**했다. 정답은 20/40이다.
   - 따라서 배포된 모델이 바뀌었거나 잘못 로드된 것이 아니다.
2. **문단 선정: 정상**
   - 답이 들어 있는 구간이 검색 상위 6개에 들어갔다. 예: 연료 질문은 2위 구간 "가스, 유류, 연탄, 목재 펠릿", 국비 질문은 1위 구간 "국비 13.5억 원".
3. **모델 원시 예측: 원인이 여기다**
   - 사이트와 같은 함수로 C-021 질문 5개에 대해 구간별 원시 예측을 기록했다.
   - presence head가 **거의 모든 구간에서 "확인 불가"(presence=1)**를 냈다.

| 질문 | 구간 | 확률 [답, 없음, 충돌] | 모델이 고른 구간 |
|---|---|---|---|
| 연료 | 답 있는 구간 | [0.367, 0.631, 0.001] | `광부 보도자료 … 4만 5,000여 가구` |
| 국비 | 답 있는 구간 | [0.363, 0.636, 0.001] | `27억 원(국비 13.5억 원` |
| 해외 식비 | 답 있는 구간 | [0.487, 0.508, 0.005] | `하루 3만원` (국내 식비, 오답) |
| 해외 숙박비 | 답 있는 구간 | [0.399, 0.596, 0.004] | 두 줄에 걸친 잘못된 구간 |
| 담당 부서 | 답 있는 구간 | [0.553, 0.444, 0.003] | `운영지원팀` (정답, 유일하게 "답 있음") |

   - 결론: 보류가 아니었더라도 고른 구간 자체가 틀린 경우가 많다.
   - **위치 검증은 실행조차 되지 않았다.** presence가 "답 있음"이 아니면 답을 내지 않는 설계이기 때문이다.
4. **결론:**
   - 배포 경로의 결함이 아니다. **모델 한계**다. "답 있음" 판정이 약하고 구간 선택 오류가 있다.
   - 수정하지 않는다. 임계값을 낮추면 틀린 구간이 답으로 나온다(예: 해외 식비 → 3만원).
5. **"probe 20/40" 표시가 사이트 동작과 다른 이유:**
   - probe는 질문마다 짧은 고정 근거 문단을 직접 준 조건이다.
   - 사이트는 업로드 문서에서 자동 검색한 128토큰 구간을 하나씩 읽힌다.
   - 조건이 다르다. probe에서도 이미 오보류가 8건이었다.
   - 카드 문구를 바꿨다(측정일, 조건, "사이트 정확도 아님", C-021 사이트 관측 0/5, "표본 5건이라 회귀 판정 아님", 원인).
   - C-021 표본 5건은 probe 40건과 조건이 달라서 회귀로 판정하지 않는다.

## 2. 기준선 Qwen3-1.7B: 정보 없음을 "근거 충돌"로 분류, 맞는 값도 위치 검증 탈락

1. **"근거 충돌" 오분류:**
   - 원시 출력은 `근거 충돌.`이다. 모델이 그렇게 생성했다.
   - RAG310에서도 보류해야 할 82문항 중 바르게 보류한 것이 2건뿐이다.
   - **모델 한계로 판단해 수정하지 않는다.** 카드 한계 문구에 명시했다.
2. **해외 식비 탈락:**
   - 원시 출력은 `[D1] 해외 출장 식비는 하루 8만원입니다.`다. 값을 문장으로 바꿔 썼고, 원문("…하루 8만원이다.")과 글자가 같지 않다.
   - 검증 설계대로 표시하지 않았다. **우회하지 않는다.**
3. **실제 결함 (수정함): 출처를 앞에 쓴 두 쌍 답을 처리하지 못함**
   - `[D1] 13.5억 원, [D2] 13.5억 원`처럼 출처를 앞에 쓴 두 쌍 답을 파서가 1쌍만 받아들였다. 그래서 위치 검증 전에 형식 단계에서 탈락했다.
   - 값을 앞에 쓰는 문법과 같이 최대 2쌍을 받도록 고쳤다. 각 값은 인용한 구간에서 글자 그대로 확인한다.
   - 테스트를 추가했다: 두 쌍 정상, 하나라도 원문에 없으면 전체 보류.
   - 실서버 재시험: 이 문항은 이제 위치 검증 단계까지 간다. 그러나 인용 구간에 값이 글자 그대로 없어 표시되지 않는다. 모델의 인용 오류다.
4. **사이트 파일과 평가 파일의 차이:**
   - 사이트 기준선은 공식 GGUF(rev `90862c4b`, `061b54da…`)이고, 카드 수치도 이 파일로 잰 것이다.
   - PILOT 비교의 원본은 같은 HF 가중치를 로컬에서 변환한 `f2ba848c…`로, 다른 파일이다.
   - 카드에 "직접 비교하지 않음"을 명시했다.

## 3. 표시 결함 (수정함)

- **문서 없이 질문할 때의 안내:** "위의 공개 문서 불러오기"를 추가했다.
