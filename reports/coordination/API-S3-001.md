# API-S3-001: 공공 API 수집 → S3 → A 임베딩 (B, 수집·저장 단일 소유)

## 결론
**완료 조건은 충족하지 못했다.** 막힌 곳은 두 군데다.

| 단계 | 상태 |
|---|---|
| 새 API 호출 | **막힘.** 인증키가 없다(1절) |
| S3 업로드 | **막힘.** root가 아닌 쓰기 주체가 없다(1절) |
| 기존 API 응답 정제 → 로컬 스냅샷 → 체크섬 재검증 → A 수집기 적재 확인 | 완료(2절) |
| A 검색에 노출 | A가 로컬 스냅샷 002를 색인 v3에 넣었다(A 커밋 `0665b56`). 일련번호 중복 71건은 건너뛰었고 새 레코드 5건이 들어갔다. 다만 새 API 수집분이 아니라 기존 수집본이다 |

"새 API 수집 완료"나 "S3 완료"라고 주장하지 않는다.

## 1. 막힌 곳 (확인 방법과 필요한 것)

**API 인증키가 없다.** 찾아본 곳:
- 이 맥의 환경변수와 셸 기록(`TRID_LAW_OC`, `serviceKey` 0건).
- `~/.config/k-skill/secrets.env`: 파일 자체가 없다.
- 맥미니(SSH)의 환경변수.
- 기존 data.go.kr 요청 기록: 134건 모두 웹 파일 내려받기다(`fileData.do`, `selectFileDataDownload.do`). API 호출이 아니다.
- 법제처 DRF 공개 시험키 `OC=test`로 1회 시도했다(`logged_get`, 요청 기록 남김). 결과는 "사용자 정보 검증에 실패하였습니다 … 서버장비의 IP주소 및 도메인주소를 등록해 주세요"였다.

필요한 것:
- 공공데이터포털 활용신청 키. 우선 후보는 기존 카탈로그(B-003-contact)의 공공기관 정보 조회 15125287, 채용정보 15125273, 사업정보 15125286이다.
- 또는 법제처 OC 키. 이 경우 이 맥 IP 등록이 필요하다.
- 키는 채팅에 붙이지 않는다. 사용자가 `0600` 파일(예: `~/.config/trid/secrets.env`)에 둔다.

**S3에 쓸 수 있는 root 외 주체가 없다.**
- 이 맥 `default` 자격증명과 맥미니 `trid-controller` 프로필 모두 `arn:aws:iam::148761639313:root`다. root는 감시 전용이라 쓰지 않았다.
- IAM 사용자는 `snowflake_s3`(무관) 하나뿐이다. 역할 `trid-sagemaker-lora`·`trid-sagemaker-c009-taskgen`은 SageMaker만 맡을 수 있다(trust principal `sagemaker.amazonaws.com`).
- 컨트롤러 정책이 쓸 수 있는 객체는 `corpus/runs/s1/controller-status.json` 하나다.
- 버킷 상태(읽기 전용 확인)
  - Public Access Block 4항목이 모두 true다.
  - 기본 암호화는 SSE-S3(AES256)다.
  - 버전 관리는 꺼져 있다.

필요한 것: root가 아닌 주체 하나와 프로필 `trid-api-writer`.
- 정책안: `deploy/api-s3/iam-policy-trid-api-writer.json`. **부착하지 않았다.** B는 IAM을 바꾸지 않는다.
  - `corpus/api/*`에 PutObject(SSE AES256 조건)와 GetObject.
  - ListBucket은 prefix `corpus/api/`로 한정.
  - HTTP 요청 거부.
- 권한이 생기면 실행할 명령:
  - 업로드: `aws s3 sync runs/api-snapshots/<id> s3://trid-training-148761639313/corpus/api/<id>/ --sse AES256 --profile trid-api-writer`
  - 재다운로드: `aws s3 sync … /tmp/<id>-readback`
  - 체크섬 확인: `scripts/build_api_snapshot.py --verify <readback 경로>`
  - 아직 실행하지 않았다.

## 2. 진행한 범위: 기존 API 수집본의 정제와 로컬 스냅샷

**입력:** `data/law-ko-source/raw/admrul/*.xml`
- 법제처 DRF Open API(`lawService.do?target=admrul`)의 원 응답이다.
- 예전에 B가 당시 키로 수집했다. 그 키는 지금 환경에 없다.
- **새로 호출하지 않았다.** manifest에도 `collection: existing_collection_no_new_api_call`로 적었다.

**코드:** `scripts/build_api_snapshot.py`. A 스키마(`HYBRID-RAG-001-SCHEMA.md`) 그대로 만든다.
- 레코드 필드: `source_id`, `version`(행정규칙 일련번호), `content_hash`, `issuer{id: 행정기관코드, name}`, `applies_to{scope: unknown}`, `dates`, `rights`, `location`, `text`.
- 추가 필드:
  - `date_kinds`: 발령일자, 시행일자, 수집 시각을 구분한다.
  - `pii`, `status`.
  - `listed_current_at_retrieval`: 수집 당시 응답의 현행여부 표시일 뿐이다. 현행이라고 부르지 않는다.
- 원 응답에 있는 담당자 이름과 전화번호는 raw(감사용)에만 남는다. normalized로 옮기지 않는다.
- PII 힌트 패턴(`trid.korean_quality.PII_HINT`)에 걸린 본문은 보류하고(`held_pii`) normalized에서 뺀다.
- 예약 평가와 겹친 행은 뺀다.
  - 기준: B-022 겹침 목록 1,004건 중 B-023 구간 검사를 통과하지 못한 행.
  - 이번 선택에서 걸린 행은 0건이다.

**스냅샷 `runs/api-snapshots/api-drf-admrul-travel-002`** (A에게 넘길 로컬 사본)
- 선택: 행정규칙 중 제목이 `출장|(?<!급)여비`에 맞는 것.
- 레코드 76건. PII 보류 4건. 원 응답 80개, 4,625,535 bytes.
- manifest sha256 `fbd00cd95f0532aecc4a5a4ea9b803ae63b2184b951cc05d9713b44bb3098edc`.
- `--verify` 결과: 파일 81개 모두 sha256 일치.
- 발행기관 상위: 대법원 7, 국토교통부 3, 농림축산검역본부 3, 우정사업본부 3, 경찰청 2, 문화체육관광부 2.

**001은 폐기했다(`SUPERSEDED.txt`).**
- 제목 필터 `출장|여비`가 '요양급여비용' 같은 비여비 규정 10건까지 골랐다.
- 002의 delta는 001 대비 new 0 / changed 0 / unchanged 76 / removed 10이다.

**같은 입력 재실행 검증**
- 001을 같은 코드로 다시 만들었다(`--previous` 사용). delta는 new 0 / changed 0 / unchanged 86 / removed 0이다.
- normalized 파일 sha256도 같다. 중복이 생기지 않는다.

**A 수집기 확인**
- A의 `scripts/build_workspace_index.api_snapshot()`이 이 스냅샷을 읽었다: indexed 76, restricted 0, empty 0.
- 001 기준으로는 86건, 구간 2,549개가 분할됐다.

**A 검색 기준 새 데이터:** A 색인 v2(`runs/workspace-index/v2`)에 같은 일련번호가 없는 것은 76건 중 **5건**이다.
- 문화체육관광부 공무 국외출장 관련 위기관리 지침 (2010-07-23)
- 농림축산검역본부 공무국외출장관리규정 (2025-07-09)
- 병무청 병역의무자 여비지급 규정 (2026-02-13)
- 농림축산검역본부 소속 상시출장공무원 여비지급 규정 (2023-12-19)
- 행정안전부 위법한 공무국외출장에 대한 지방자치단체 처리기준 (2026-06-19)

나머지 71건은 v2에 이미 있다. 같은 문서를 두 번 색인하지 않으려면 A가 `location.url`의 `ID=`(일련번호)로 중복을 제거해야 한다.

## 3. A와의 계약 (HYBRID-RAG-001-SCHEMA.md 합의)
- 스키마를 그대로 따른다. 필드는 추가만 했다(`date_kinds`, `pii`, `status`, `collection`, `listed_current_at_retrieval`, `rule_kind`, `amendment`, `issue_no`).
- **날짜 표시:** A의 수집기는 `dates.published`를 '공표일'로 표시한다. 행정규칙에서 이 값은 **발령일자**다. `date_kinds.published`를 표시명으로 써 달라.
- **issuer.id:** ALIO apbaId가 아니라 행정기관코드다(`issuer.id_scheme`).
- **기관 별칭:** A가 이미 ALIO 공식 목록(`data/corpus-inventory/alio-agencies.json`)으로 연결한다. 이번 레코드의 발행기관은 중앙행정기관이라 행정기관코드로만 식별한다.
- **structured_facts:** 이번 규정 본문에서는 뽑지 않았다(0건).
  - 금액·단위·기간을 표 행·열까지 검증하는 단계가 아직 없다.
  - 정형 값은 실 API(통계·공시)가 열리면 `basis`를 구분해 넣는다.
- **폐쇄망 반입:** 스냅샷 디렉터리 하나(manifest, normalized, raw)가 반입 단위다. 실행할 때 외부 API에 의존하지 않는다.

## 4. 요청·비용
- 이번 작업의 외부 요청은 law.go.kr DRF 1회다(실패 응답 293 bytes, `logs/requests-law.go.kr.jsonl`).
- AWS 호출은 읽기 전용 확인뿐이다: sts, iam list-users/list-roles/get-role, s3api 버킷 설정 3종.
- S3 쓰기 0. 추가 비용 0원(S3 저장·요청 없음, compute 없음).
- 로컬 사용량: 스냅샷 002는 약 5 MB.

## 5. 남은 것
1. 사용자: 공공데이터포털 또는 법제처 키를 0600 파일로 둔다.
2. 사용자: `trid-api-writer` 주체를 만들고 정책안을 부착한다.
3. 1·2가 되면 B가 할 일:
   - 15125287을 실제로 호출하고, 요청 단위 원 응답·페이지 누락·기준일을 기록한다.
   - 같은 스냅샷 형식으로 S3에 올리고 재다운로드 sha256을 검증한다.
   - 그 결과를 이 보고서에 덧붙인다.
4. A: 002를 `--api-snapshot`으로 색인한다. 일련번호로 중복을 제거한 뒤 위 5건이 검색되는지 확인한다.
