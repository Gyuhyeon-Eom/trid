# B-023: 값 불일치 원인 판정, HWPX 대조 오류 정정, 예약 겹침 102행의 구간 단위 검증

## 요약
- **search-corpus-v4**: v3와 구간이 같다(ID·오프셋·본문·sha256 동일). 바뀐 것은 값 대조 필드뿐이다.
  - HWPX 대조기 결함을 고쳤다. 불일치 문서가 4건에서 1건으로 줄었다.
  - PDF 불일치 245구간에 `value_review`(숫자별 원인과 판정)를 붙였다.
- **원문 오타로 확정한 값은 0건이다.** 그래서 고친 본문도 없다. 설명되지 않는 값과 추출 결함은 값 사용을 보류한다.
- **예약 겹침 102행을 구간 단위로 다시 봤다.** 모든 공유 구간이 법령 본문인 행은 69건이다. 나머지 33건은 평가 색인과 분리한다.
- **이번에 하지 않은 것:** LH 사규 별도 검색 후보 구축, 기관 실무자료 추가 수집. 우선순위가 API-S3-001과 MODEL-REPAIR로 바뀌었다(4절).

## 1. HWPX 대조: B-022의 원인 추정을 정정
- B-022는 큰 편람 3건의 불일치를 "목록 자동 번호로 보인다 [추정]"고 적었다. **틀렸다.**
- 실제 원인은 대조기가 원본 XML을 덜 읽은 것이다. 추출 결과에는 문제가 없었다.
  - `<hp:t>` 안에 `<hp:tab/>` 같은 하위 요소가 있는 run을 통째로 놓쳤다. 15038798 한 문서에만 3,396개가 있다.
  - 속성이 붙은 `<hp:t …>` run도 놓쳤다.
  - 수식 객체(`<hp:script>`)를 읽지 않았다.
  - 마크다운 이미지 참조(`image_052.bmp`)의 파일명 숫자를 값으로 셌다.
- 수정: `scripts/annotate_search_pages.py`의 `hwpx_text`와 `MARKUP`.

| 문서 | v3 | v4 |
|---|---|---|
| 15038798 지방재정 해설사례집 | differ (1,502) | differ: '2006', '2005' 각 1회 초과 |
| 15038493 행정업무운영 편람 | differ (268) | agree |
| 15033217 충남 계약심사 사례집 | differ (524) | agree |
| admrul-file 156743739 | differ (4) | agree (수식 `{8,000} over {15,000}`) |

- 15038798에 남은 2개: 추출본의 등장 위치마다 앞뒤 25자 문맥이 XML 본문에 있다. 개수만 하나씩 많다.
  - 구간끼리 겹치지 않고, 같은 본문 구간도 없다. 원인은 아직 확인하지 못했다.
  - 값이 원본에 없는 경우는 아니다.
- 재발 방지 테스트: `tests/test_annotate_search_pages.py`. 고치기 전 코드에서는 실패한다.

## 2. PDF 불일치 245구간: 숫자별 원인과 판정
- 각 숫자를 원본 `pdftotext -layout`과 `-raw` 텍스트로 다시 대조했다(`number_class`).

| 원인 | 숫자 수 | 의미 | 판정 |
|---|---|---|---|
| separator_spacing | 60 | 원본에 '.', '-', ':' 뒤 공백·줄바꿈만 다르게 있다('2008.\n8.11') | 원본 쪽 표시 |
| letter_spaced | 2 | 원본이 한 글자씩 띄워 인쇄했다('0 . 1 3 4 6') | 원본 쪽 표시 |
| elsewhere_in_pdf | 71 | 같은 PDF 다른 쪽에 있다 | 원본 쪽 표시 |
| elsewhere_in_pdf_short_number | 261 | 1~2자리 수가 다른 쪽에 있다(약한 증거) | 원본 쪽 표시 |
| print_production_mark | 33 | 인쇄용 표식 줄('… .indd 1 12.4.30.')이다. 본문이 아니다 | 원본 쪽 표시 |
| equation_object | 166 | 수식 객체($…$). PDF 텍스트층에 없다 | **보류** |
| merged_tokens | 16 | 원본에서 따로 있는 칸·토큰이 추출 때 붙었다('1 2 3 4 5'→'12345', '2019-01-01 00'→'2019-01-0100'). 원본에 없는 수다 | **보류** |
| doubled_glyphs | 1 | 겹쳐 찍힌 글자가 두 번 읽혔다('20○○년'→'2200○○○○년년') | **보류** |
| image_only_page | 3 | 해당 쪽에 텍스트층이 거의 없다(200자 미만). 대조할 수 없다 | **보류** |
| redaction_residue | 3 | 전화번호 치환 뒤 내선 번호 조각이 남았다('[전화]4039', '2117, 2119') | **보류 + 개인정보 검토** |
| not_in_pdf | 1 | 위 어디에도 해당하지 않는다(15043134 '1.1') | **보류** |

- 구간 판정: 보류 87(법령 첨부 68, data.go.kr 19), 원본 쪽 표시 158. 개인정보 검토 2구간은 행정규칙 첨부 168423963이다.
- **원문 오타는 확정하지 못했다.** 원본과 다른 숫자는 모두 추출 결함(칸 붙음, 글자 중복, 수식)이거나 대조 불가다. 그래서 본문을 고치지 않았다. 본문을 고치면 구간 sha256이 바뀌는데, 그럴 근거가 없다.
- **[추정] 판정 규칙의 한계**
  - '한 칸씩 띄운 같은 토큰'(-layout에서 모든 글자 사이 공백이 1칸)과 '따로 있는 칸'(공백 2칸 이상)을 공백 폭으로 구분했다.
  - -raw 출력은 칸 간격을 1칸으로 줄이므로 글자 간격 판정에 쓰지 않았다.
  - 1~2자리 수는 이웃 칸 숫자와 우연히 맞을 수 있어 유연 대조에서 뺐다.
- 값이 원본에 있다는 것만 확인했다. 표의 행·열 배치까지 검증한 것은 아니다.

## 3. 예약 겹침 102행: 구간 단위 검증
- B-022는 행 단위 비율로 판정했다: 공유 8-gram의 80% 이상이 법령 문구이면 `index_ok`. 이 방식은 나머지 20%를 확인하지 않는다.
- 이번 방법(`scripts/verify_overlap_spans.py`)
  - 공유 8-gram이 덮는 최대 연속 구간을 하나씩 확인했다.
  - 구간 전체가 수집된 법령 본문 한 건(`law-go-kr:law:*`, 자기 자신 제외) 안에 단어 그대로 있으면 `statute_span`으로 본다.
  - 행 자체가 법령이면 `own_statute_span`으로 본다.

| 수집본 종류 | 모든 공유 구간이 법령 본문 | 법령 밖 구간 있음 → 평가 색인과 분리 |
|---|---|---|
| 법령 (law) | 65 | 0 |
| 행정규칙 (admrul) | 0 | 26 |
| 해석례 (expc) | 4 | 7 |

- 구간 수: statute 1,567, own_statute 1,814, non_statute 116.
- 법령 밖 구간의 예
  - 민원처리 규정의 기관별 문구.
  - 감사 재심사 사유 목록.
  - 예전 문안의 법령 인용. 예: 개인정보 정의, 부정당업자 조항. 수집된 법령 본문과 글자가 달라 법령으로 확정할 수 없다.
- 법령 본문이라고 확정할 수 없는 구간은 허용하지 않았다. 69건만 검색 색인 후보다. 학습 승인은 아니다.
- 결과: `B-023/overlap-102-span-check.jsonl` (+ `.summary.json`, 커밋 `863ecb5`).
- API-S3-001 스냅샷도 같은 목록을 써서 겹친 행을 뺀다.
