# 각주 참조와 원래 구획에 대한 C 제안 계약 (C-015 → B 확인 요청)

**상태:** C가 제안했고 B가 확인해야 한다. B가 확인하기 전에는 C의 각주 사례(`C-015/batch-footnotes`의 신규 118건)를 A에게 학습 후보로 넘기지 않는다.

## C가 B v3-norm2에서 쓰는 것

`meta.normalization.edits` 중 `rule == "footnote"`인 편집만 쓴다. 붙임·띄어쓰기·엔티티 규칙은 쓰지 않는다(전체 승인 보류).

| 필드 | C가 기대하는 의미 |
|---|---|
| `src_start`, `src_end` | 원본 v3 `text`(sha256 = `meta.normalization.source_sha256`)의 offset이다. 범위는 본문 안의 각주 전체(`N)N) 본문` 끝 줄바꿈까지)다. |
| `replacement` | `[각주N]`이다. N은 원본 표지 `N)N)`의 N과 같다. |
| 각주 본문 | `text[src_start:src_end]`에서 앞의 `N)N)`을 빼고 앞뒤 공백을 지운 문자열이다. 한 글자도 바꾸지 않는다. |

## C 빌더의 처리 (`scripts/build_internal_cases.py --footnotes`)

1. 원본 v3 글에서 질의요지(‹질의 배경› 앞까지), 회답, 이유(법령정비 권고·관계 법령 앞까지) 구획을 offset으로 나눈다.
2. 각 구획 안의 각주 편집만 `[각주N]`으로 바꾸고, 그 구획 끝에 `[각주N] 본문`을 인용 순서대로 붙인다. 질의요지의 전제·정의는 질문에 남고, 이유의 각주는 근거에 남는다.
3. 다음 경우에는 그 행으로 사례를 만들지 않는다.
   - 구획 경계를 넘는 각주가 있다.
   - 한 구획 안에서 표지와 본문이 1:1로 맞지 않거나, 같은 번호가 되풀이된다(원문이 구획마다 번호를 다시 1부터 매겨 참조가 모호한 경우).
   - 같은 본문이 두 구획에 붙는다(정의 반복).
   - 처리 뒤에도 `N)N)` 형태가 남는다(편집되지 않은 각주).
4. 원본 v3의 sha256과 편집의 `source_sha256`이 다르면 빌드를 중단한다.

## B에 확인을 요청하는 것

- 위 필드 의미가 B 코드(`normalize_interpretations.py`)와 같은지 확인해 달라.
- 번호가 구획마다 다시 매겨진 문서 7건과, 표지가 깨진 1건(`expc:339505`, "7)1) 1)")을 B가 따로 처리할지 정해 달라. 지금은 사례에서 빠진다.
- 이 계약은 각주 이동 규칙만 쓴다. 다른 정규화 규칙의 승인과는 관계없다.
