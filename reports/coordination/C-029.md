## 1. 지금 검증한 것 (합성, 로컬 서비스 코드)

### 1.1 privacy_review: 높은 순위여도 완전히 제외

| 조건 | 해당 구간 순위(점수) | select | hits(상위 5) | 모델 context chunks |
|---|---|---|---|---|
| 표시 없음 | **1위 (0.959)** | answer | 포함 | **포함**(@0, @1040) |
| privacy 표시 | 76,265위 (0.0) | answer | 없음 | **없음** |

- **통과.** 질문에 가장 잘 맞는 구간이어도 표시되면 검색 순위, 후보, 모델 입력, 응답에서 빠진다.
- **관찰된 부작용:** 그 구간이 빠지자 서비스가 같은 법령의 다른 별표(별표 6 국외 가족여비 지급 기준표)로 답했다. 개인정보 문제는 아니다. 다만 보호 구간이 빠진 자리를 관련도가 낮은 문서가 채우는 대체 위험이 있다.

### 1.2 hold_for_value_use: 숫자를 답 근거로 쓰지 않고 원문 안내

- 질문: 국가공무원 복무규정 경조사별 휴가 일수표에서 본인 결혼 휴가는 며칠인가요?(그 문서 고정)
- **select:** chunk에 `value_hold=True`가 붙었다.
- **case 모드 실제 모델 응답:**
  - status `unverified`. 확인된 인용이 0건이라 값을 답으로 표시하지 않았다.
  - 숫자가 들어 있는 해설 문장 **5개를 숨겼다.**
  - 안내: "숫자 추출이 원문 쪽과 일치하지 않는 구간 1개를 썼습니다. **이 구간의 숫자는 답 값으로 쓰지 않으니 원문(쪽)에서 직접 확인하세요.**"
  - 남은 해설에도 숫자(5일)가 없다.
- **통과(case 모드).**
- **미관찰:** 값만 답하는 버전(기준선, v0.1)에서 hold 구간을 아예 읽지 않는 동작은 서버 요청 처리 안에 있다. 이번 로컬 함수 호출로는 관찰하지 못했다. v0.1은 실사이트에서 HTTP 422(C-026 S14)라 실 UI로도 확인할 수 없었다.

### 1.3 실제 보호 구간 (id 대조)
