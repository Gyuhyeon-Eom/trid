## 2. 설계 (`scripts/shared_demo.py`, `deploy/shared-demo/versions.json`)
- **기본 버전:** `trid-assistant-qwen3-1.7b`. Qwen3-1.7B 원본 GGUF이며 업무 특화 학습은 하지 않았다. 표시명은 "TRID 기본 · Qwen3-1.7B 원본 (업무 특화 학습 없음)"이다. 기준선과 llama-server(:51912)를 공유한다.
- **pilot 표시:** "TRID 1.7B · 실험판 (특화 시도 · 회귀)". 한계 칸의 "미확인(C 평가 중)" 문구는 회귀 사실로 바꿨다.
- **경로 선택(`route`):**
  - 서비스 모델 자신이 GBNF `root ::= "검색" | "대화"`로 입력만 보고 고른다. 키워드 규칙, 고정 응답, 질문별 예외는 없다.
  - 직전 대화를 함께 넣어 봤지만 1.7B가 분류 대신 대화를 이어 갔다. 그래서 입력만 넣는다.
  - 직전 턴이 근거 검색이면, 입력에 기관·문서명이 없고 직전 문서가 이 입력에 대해 전체 최고 BM25 점수의 60% 이상(기존 `WEAK`)이면 이어지는 검색으로 본다(`Workspace.continues`).
  - 두 번째 분류기("작성/규정")도 시험했다. "고마워"를 규정으로 0.998 확률로 분류할 만큼 불안정해서 쓰지 않았다.
- **일반 대화(`chat_reply`):**
  - 모델의 기본 chat template에 최근 6개 메시지를 넣는다. 저장 위치는 세션 메모리다.
  - 근거 검색을 하지 않는다. 숫자+단위(원·%·일·개월·조·항 등)가 들어간 문장은 숨기고 숨긴 개수를 알린다. 숨긴 원문은 API 응답에도 넣지 않는다.
  - 표시: "일반 대화 · 문서 근거 없음 · 검증 대상 아님". 시스템 프롬프트는 기관 규정 사실을 기억으로 답하지 말라고 하고, 한국어만 쓰게 한다.
- **근거 검색:**
  - 기존 case 모드를 그대로 쓴다. 원문과 글자 그대로 일치하는 인용만 확인된 근거로 표시하고, 모델 해설은 "검증 안 됨"으로 표시한다.
  - 기관이 모호하면 되묻는다.
  - 자료에 없는 기관이거나 일치하는 문서가 없으면 모델을 실행하지 않고 안내한다. **이때 일반 대화로 넘기지 않는다.**
- **이어지는 질문(`Workspace.select(context_doc=)`):**
  - 이름이 없는 이어지는 질문은 직전 턴의 적용 문서에서 찾는다. 응답에 `workspace.continued=true`를 넣는다.
  - 기관·문서명을 적으면 그쪽이 우선한다. 직전 문서와 관련이 약하면 이어서 찾지 않는다.
  - 검색어를 모델이 다시 쓰게 하는 방식은 버렸다. 시험해 보니 모델이 질문을 고쳐 쓰지 않고 지어낸 답을 검색어로 만들었다.
- **대화 기억과 근거의 분리:**
  - 검색 턴은 대화 기억에 `[근거 검색 결과] …(적용 문서 …)` 요약으로만 남는다.
  - 근거는 매 질문마다 색인에서 다시 찾는다. 대화 기억은 근거로 쓰지 않는다.
- **세션:** `/api/clear`는 대화 기억도 지운다. 15분 동안 쓰지 않으면 문서와 대화 기억을 정리하는 동작은 그대로다.
- **제목 매칭:** 질의회신(Q&A) 문서의 제목은 방문자가 쓴 질문이므로 문서명 매칭에서 뺐다. C-024가 지적한 "숙박비 상한 → 무관한 권익위 Q&A" 오분류의 원인이다.
- **서버 구성:**
  - `State`는 추출 독해기가 하나라도 있으면 된다(업로드 문서 분할용 토크나이저).
  - `"default": true` 버전을 미리 선택해 둔다.
  - 같은 모델 파일·실행 파일·context를 쓰는 버전은 llama-server를 공유한다.
- **UI 소유권:**
  - UI(`trid/shared_ui/*`)는 사용자 지시에 따라 B가 단독으로 맡는다. A의 마지막 UI 상태는 `c8b148b`다.
  - API 계약: `reports/coordination/A-UI-API-CONTRACT-001.md`.

## 4. 알려진 한계
- 1.7B 원본의 대화 품질은 제한적이다. 예: 문장 다듬기 결과가 거의 바뀌지 않음, 감정 대화가 상투적임.
- 업무 질문은 글자 그대로 일치하는 인용이 없어 "검증 안 됨" 해설만 나오는 경우가 많다.
- 대화 경로에서 숫자 없는 규정 서술은 숨기지 못한다. 시스템 프롬프트와 "검증 대상 아님" 표시에 의존한다.
- 2-word grammar 라우터의 판단은 1.7B의 한 번 탐욕 디코딩 결과다. 개발 측정 27개 밖의 정확도는 측정하지 않았다.
- case 모드는 질문과 관련 없는 짧은 원문 조각(편람 제목, 발행일)도 "원문 인용 확인됨"으로 표시할 수 있다. 실사이트 "강등의 효력은?"에서 확인됐다. 이는 글자 일치만 확인했다는 뜻이며, 관련성 검사는 별도 과제다.
- 응답의 `workspace.continued`를 UI가 아직 표시하지 않는다(B 담당). 응답의 `scope` 문장에는 들어 있다.

## 5. C 독립 검증 계약 (A는 실행하지 않음)
- **대상:** 배포 후 https://test.tridatum.co, 기본 버전.
- **확인 항목:**
  1. 인사·서비스 문의·잡담이 `intent:"chat"`이고, 출처·인용 블록 없이 "검증 대상 아님"으로 표시되는지.
