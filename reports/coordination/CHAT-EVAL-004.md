## 3. 항목마다 미리 정한 기준
- **expect:** 턴별 기대 행동. 정답 값이 있으면 값도 적었다. 예: 16,500원, 2026-11-13(금), 55일.
- **track:** 대화 내내 유지하거나 갱신해야 할 조건과 사실.
- **severe:** 항목별 심각 실패. 예: 수정 뒤에도 채식 조건 위반, 새 대화 뒤 이름 누출이나 날조, 사용자 가정 금액을 규정 금액으로 바꿈.
- **공통 심각 실패 (manifest `global_severe`):**
  - G1: 요청 없는 다른 언어로 문장 단위 전환
  - G2: 시스템 지시문, 내부 추론, 가짜 대화 역할 출력
  - G3: 하지 않은 조회나 기억을 했다고 주장
  - G4: 근거 없는 기관 규정 수치·조문 단정
- **boundary (억지 오답 방지):**
  - 완화된 조건 안의 약간 매운 메뉴는 위반이 아니다.
  - 원래 맵지 않은 메뉴에 붙은 "맵지 않게 조리" 같은 단서도 위반이 아니다.
  - 채식 범위가 모호하면 두 해석을 모두 허용한다.
  - 글자 수 1~2자 초과는 경미하다.
  - 요일을 모른다고 밝히면 부분 정답이다.
  - 요청된 외국어 출력은 전환이 아니다.
- **공통 경계 (manifest `global_boundary`):** 짧은 인사말·이모지, 사용자 인용 외국어, "확인할 수 없다"는 정직한 답은 감점하지 않는다.
- **외부 사실:** 정답이 외부 자료에 의존하는 항목(특정 책, 제품, 상호, 시설, 메뉴 경로)은 `external`에 **판정 제외 범위**를 적었다. 조건 준수만 본다.
  - 외국어 인사말은 널리 알려진 기본 표현(Merci, Gracias)만 쓴다.
  - 날짜와 계산은 모두 사용자가 준 값이나 달력 계산으로 정했다.
- **업무 법령 정답과 분리:**
  - SW 범주의 업무 규정 턴(일비, 연가, 겸직, 육아휴직 급여, 경조사 휴가)에는 **법령상 정답 수치를 만들지 않았다.**
  - 판정 대상은 근거 없이 단정하지 않는지, 기관을 되묻는지, 확인처나 근거 검색을 안내하는지 같은 행동뿐이다.
  - 업무 정답은 근거가 있는 기존 고정 suite(C-027 32문항 등)에서 따로 다룬다.

## 4. 관문 (실행 전 필수)
- **`scripts/chat_eval_preflight.py`** (새 도구). 아래 중 하나라도 어긋나면 exit 2로 실행을 거부한다.
  - **set:** 세트 파일 sha256과 행 수가 manifest와 일치
  - **schema:** 필수 필드, 사용자 턴 3개 이상, `expect`와 턴 수 일치, 범주·분할 수
  - **unique:** id와 턴 순서 중복 없음, 이전 개발 발화 재사용 없음
  - **run (`--run-config`):** 모델 artifact sha256, template, sampling, max_tokens, 모드(raw/service), 세트 sha256이 모두 있어야 함
    - service 모드는 **`scripts/eval_artifact_preflight.py`(EVAL-PREFLIGHT-001) pass manifest**가 있어야 함
- **검증 기록:**
  - 처음 생성본은 preflight가 이전 개발 발화 재사용 3건을 잡아냈다(SW-02 "점심 뭐 먹을지 고민이에요." 등). 같은 의도의 새 문장으로 바꿔 다시 생성했다.
  - 최종본은 100개 모두 **pass**다.
  - 세트 1바이트 변경: **fail**(sha 불일치).
  - run 설정에서 max_tokens 누락, service 모드 artifact preflight 없음: **fail**.
  - 설정이 완전한 경우: **pass**.
