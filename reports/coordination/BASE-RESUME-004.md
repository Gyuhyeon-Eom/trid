## 1. 준비한 것

### `scripts/base_dialogue_runner.py` (`947d4c9`)

**실행 방식**
- 모델 하나를 격리 포트(:51990)에서 순차로 실행한다.
- 같은 llama.cpp `8ca4060` Metal `llama-server`, `-c 4096 -np 1 -t 4 --jinja`.

**manifest에 남기는 것**
- 모델 파일 sha256과 기대값 대조(`--expected-sha256`, 불일치면 중단)
- 공식 출처와 고정 revision(입력 그대로 기록)
- 내장 chat template의 원문과 sha
- 공식 HF tokenizer가 로컬에 있으면 렌더링 일치 검사(다운로드 없음)
- 요청한 sampling과 그 출처
- 서버 기본값, 첫 completion이 보고한 실효 generation settings
- EOS·BOS
- history 정책: 대화마다 자기 답으로 history를 쌓고, `__CLEAR__`이면 새 대화
- 시작·종료 시 메모리 상태와 실서비스 상태

**턴마다 남기는 것** (`turns.jsonl`)
- 렌더링된 프롬프트 문자열, 프롬프트 토큰 ID
- 출력 원문, 출력 토큰 ID
- stop 종류, stopping word, timings, 실제 걸린 시간

**안전장치**
- 대화를 시작할 때마다 메모리 압박 단계를 본다. 1이 아니거나 실서비스가 running이 아니면 그 자리에서 멈추고 부분 결과를 남긴다.
- 출력 디렉터리가 비어 있지 않으면 실행을 거부한다(덮어쓰기 금지).

**하지 않는 것:** 재시도, 출력 필터, 질문별 처리, 문자 차단.

**도구 점검:** 기존 Qwen3-1.7B로 두 턴짜리 임시 파일을 돌렸다(새 평가가 아니라 도구 점검이다).
- 공식 HF 렌더링과 일치했다.
- 실효 설정이 기록됐다: temperature 0.7, top_k 20, top_p 0.8, min_p 0, repeat 1.0, presence 0.
- 토큰 ID도 기록됐다.
- 점검 출력은 지웠다.
