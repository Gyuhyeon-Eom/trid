# BASELINE-COMPARE-002: 같은 맥북·같은 llama.cpp에서 Qwen3-1.7B 대 Qwen2.5-7B 일상 대화 비교

**상태: 완료.** 두 모델 모두 개발 대화 13개 × seed 3을 끝냈다.

**결과 요약** (개발 비교, 평가 아님)
- 두 모델 모두 일상 대화 품질 기준에 못 미친다.
- 7B는 번역 핵심을 지키고 생략형 후속을 맞게 받았다. 대신 **중국어 전환이 26/141턴**으로 심하다.
- 1.7B는 반복이 많고 번역 핵심을 놓친다.
- 다듬기 지시 수행은 두 모델 모두 약하다.

**해석 제한**
- 두 모델은 세대(Qwen2.5 대 Qwen3)와 크기(7B 대 1.7B)가 함께 다르다. 그래서 어떤 차이도 파라미터 수의 인과로 해석하지 않는다.
- 7B가 나은 항목이 있어도 운영 품질 합격은 아니다.
- 기본 모델은 바꾸지 않는다.
- 새 학습, 튜닝, 외부 다운로드, AWS는 모두 0이다.

**표본을 직접 읽고 확인한 것** (휴리스틱 수치 해석 시 주의):
- **Qwen3 S3의 0/9:** 위반 단어는 없다. 다만 내용이 부실한 답이 섞여 있다. 예: 디저트로 "무, 브로콜리, 계란"을 추천하거나, 메뉴 대신 되묻기만 함. 0/9를 좋은 추천으로 읽지 않는다.
- **Qwen2.5 S3의 2/9:** 휴리스틱이 걸린 경우에는 "매운 라멘을 피…"처럼 피하라는 문장과 섞인 표현이 있다. 위반 수는 대략이다.
- **Qwen2.5 언어 전환:** 한국어로 시작해 중국어로 바뀌거나 턴 전체가 중국어인 경우가 있다.
  - 예: S2 1·2턴 전체가 중국어
  - 예: S3 2턴 "…고르는 것도挺好的，…"
  - 예: S4 1턴 "自动生成的资料请在明天之前提供给您。"
  - 이 때문에 한국어 일상 대화에는 그대로 쓸 수 없다.
- **다듬기:** 두 모델 모두 앞 결과를 이어서 고치는 대신 새 문장을 만들거나 뜻을 바꿨다. "처음 버전 다시"는 거의 실패했다.
- **속도:** 같은 맥, 같은 런타임에서 잰 값이다. 7B는 더 크고 느리다. 속도 차이는 품질의 우열이 아니다.

## 3. 결론과 다음 판단 (사용자·감독 결정)

- 이 개발 비교에서 Qwen2.5-7B는 번역 핵심과 생략형 후속에서 Qwen3-1.7B보다 나았다. 언어 섞임(26/141)과 잘림(14/144)은 더 나빴다. 다듬기 지시는 둘 다 약하다.
- 어느 쪽도 자동으로 기본값이 되지 않는다. 7B는 지금 상태로는 운영 후보도 아니다(중국어 전환 때문).
- 차이를 파라미터 수의 효과로 해석하지 않는다. 세대, 학습 데이터, 양자화(Q8_0 대 Q4_K_M)가 함께 다르다.
- C-031 업무 지표는 C 정정본(`C-031-METRICS-CORRECTION.md`)만 인용한다.
  - 엄격 내용 정확 10 → 12. 차이는 약칭 2건이 무응답에서 정답으로 바뀐 것뿐이다. 나머지 23건은 문서와 해설이 글자까지 같다.
  - 그러므로 해설 능력이나 모델 품질이 나아진 증거가 아니다.
  - "같은 기관 다른 문서 정확 1", "이유 오류 1"은 각각 별도 항목이다. 둘을 더해 14건 정확으로 셈하지 않는다.
- 추가 비교(다른 설치 모델, 다른 양자화, 프롬프트 변형)와 새 학습은 지시 없이는 하지 않는다.
- **정리:** 복사한 7B GGUF(4.7 GB, `runs/` 아래, git 추적 안 함)는 재현용으로 남겨 두었다. 삭제가 필요하면 지시를 받아 지운다.
