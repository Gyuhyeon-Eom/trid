## 2. 원문 덮어쓰기 차단

### 코드 수정 (커밋 `33bd65c`)

**`put_new`:**
- 원문은 S3 조건부 쓰기(`If-None-Match: *`)로만 쓴다.
- 키에 이미 객체가 있으면 S3가 쓰기를 거부한다.
- 같은 바이트면 기존 해시를 돌려주고 쓰지 않는다.
- 다른 바이트면 `RawExists`를 내고 아무것도 바꾸지 않는다.

**국회 `fetch`:**
- 버전과 관계없이 원문이 저장된 회의는 요청하지 않는다.
- 이전 실행에서 HTTP 4xx를 받은 회의도 다시 요청하지 않는다. 다시 받으려면 `--retry-failed`를 명시해야 한다.
- 경쟁 상황 등으로 쓰기 단계에서 원문이 이미 있으면 기존 원문을 유지하고, 그 회의는 실패(`raw_exists_not_overwritten`)로 기록한다.

**ALIO 수집기의 원문 쓰기 경로(요청은 계속 중단):**
- `put_raw_keep`을 쓴다.
- 일부러 다시 받아 바이트가 달라진 경우에는 기존 객체를 두고 새 바이트를 `<stem>.<sha256[:16]>.<ext>`라는 별도 키에 저장한다. 상태 기록에 실제로 쓴 키를 남긴다.

**아직 바꾸지 않은 경로:**
- FineWeb `raw_copy`는 객체가 있는지 먼저 확인한 뒤 업로드한다. 조건부 쓰기가 아니다.
- FineWeb 확대가 보류 중이라 이번에는 바꾸지 않았다.

## 3. 요청 간격: 예약 시각이 아니라 실제 시작 시각 기준

**원인:** 이전 `HostLimiter`는 시작 시각을 **예약**해 1 s 간격을 맞췄다. 그래서 한 요청이 늦게 깨어나거나 보내기 전에 멈추면, 다음 요청과의 실제 간격이 1 s보다 짧아졌다. B-008 실측 최소 간격 0.9906 s가 그 결과다.

**수정 (`HostLimiter.slot`, 커밋 `33bd65c`):**
- 한 호스트에는 요청을 하나씩만 보낸다.
- 다음 요청은 **이전 요청이 끝난 시각(응답 본문 수신 또는 실패) + 간격** 이후에 시작한다.
- 대기는 한 번 계산하고 끝내지 않는다. 잠에서 깰 때마다 실제 시계로 다시 확인한다.
- 여러 프로세스가 한 잠금 파일을 공유한다. 요청이 진행되는 동안 배타 파일 잠금을 쥐고 있다.

**이 설계가 간격을 보장하는 이유:** 요청 바이트는 시작 뒤, 끝 전에 나간다. 다음 요청은 이전 요청의 끝 + 간격 이후에 시작한다. 따라서 실제 송신 간격은 항상 간격보다 크다.

**대가:** 실효 속도는 1/(간격+응답시간)으로 떨어진다. 로컬 측정에서 0.71–0.84 req/s였다. 평균이 1 req/s 미만이라는 사실만으로 순간 간격 위반이 면제되지는 않으므로, 아래는 서버 측 최소 간격으로 판정했다.

**로컬 HTTP 서버 측정** (`B-009/proof-actual-gap.json`, 스크립트 `B-009/proof_actual_gap.py`):
- 조건: 실제 정책 간격 1.0 s, 원격 요청 없음.
- 서버 측 시각은 핸들러가 요청을 받은 시각이다.

| 시나리오 | 요청 | 서버 측 최소 간격 | 1 s 미만 간격 | 1초 창 최대 | 기록 최소 간격 |
|---|---|---|---|---|---|
| 단일 프로세스·스레드 1 | 10 | **1.0631 s** | 0 | 1 | 1.0632 s |
| 프로세스 3개 (하나는 스레드 3) | 12 | **1.0175 s** | 0 | 1 | 1.0176 s |
| 같은 구성 + 늦은 기상(대기마다 +0–120 ms) + 송신 전 정지(0–200 ms) | 12 | **1.1976 s** | 0 | 1 | 1.2133 s |
| 참고: 이전 예약 설계(`940a83c`), 같은 오작동 | 12 | 0.8899 s | **7** | **2** | 0.9241 s |

**상시 테스트:**
- 이전의 예약 시각만 검사하던 테스트 2개를 아래로 대체했다.
- `test_requests_reach_the_server_spaced_across_processes_threads_late_wakeups_and_stalls`
  - 로컬 서버, spawn 프로세스 2개, 스레드 3개, 늦은 기상과 송신 전 정지를 넣는다.
  - 서버 측 도착 간격이 간격 이상인지 검사한다. 허용 오차는 두지 않았다.
- `test_retry_after_pushes_the_next_request_out`
  - 429와 `Retry-After: 1`을 받으면 다음 요청이 1 s 이상 뒤에 도착하는지 검사한다.

**새 제한기의 실제 원격 사용:** PRISM 정적 파일 3건(5절)뿐이다. 이전 요청 종료부터 다음 시작까지 3.551 s, 1.010 s였다. 국회 추가 수집은 없었다. 대상이 남아 있지 않다(2,140건 저장, 2건은 요청 금지).

`www.prism.go.kr`는 React SPA다. 백엔드는 `api.prism.go.kr`이다.

공개 번들(`main.9fad982f.js`)에서 확인한 사용권 표시:
- 보고서마다 공공누리 유형 코드가 있다(`koglTypeCd`: D0590002 1유형, D0590006 자유이용, D0590003–05 2–4유형).

- 공식 API가 인증키를 요구하는 상황에서, 사이트 내부 백엔드(`/v1/entire/*`, `/v1/progress/download-file`)를 직접 호출하면 인증키 요건을 우회하는 것이 된다.
- `api.prism.go.kr`에는 robots.txt가 없다(404). robots.txt가 없다고 허용으로 보지 않는다(B-INVENTORY-001).

**TLS:**
