## 2. 결함과 원인

`aggregate`가 같은 reviewer_type의 판정 중 첫 번째를 `next(...)`로 골랐다. 서로 다른 전문가 두 명이 같은 문항을 정답/오답으로 판정하면 입력 순서에 따라 점수가 1.0/0.0으로 바뀌었다(총괄 재현과 동일). 검증 단계는 같은 reviewer_id의 중복만 거부하므로, 다른 검수자의 의견 불일치는 정상 입력이었고 첫 판정 선택이 이를 숨겼다.

## 3. 수정 내용과 합의 규칙

- **문항 상태(검수자 유형별, 순서 독립)**: 판정 없음 `unreviewed`. 모든 판정이 결론·근거 판정·조건/예외 누락 판정·허위 주장 유무까지 같으면 `settled`(판정 수와 무관하게 문항 1개로 셈). 하나라도 다르면 `disagreement`(재검수 필요, 어떤 판정도 선택하지 않음). 한 명이라도 `불확실`이고 다른 명이 결론을 내면 `disagreement`. 모두 `불확실`이면 `uncertain`.
- **유형 분리**: AI·human·expert 판정은 섞거나 투표하지 않는다. 같은 문항에 AI 정답·expert 오답이 있으면 각 유형 안에서 각각 settled.
- **원본 보존**: 집계 보고서에 모든 판정 행을 그대로 포함(`verdicts`). 재검수 대상 패킷 코드를 `rereview_needed`로 열거. 재검수 합의가 있었다고 만들지 않는다.
- **점수 표기**(필드 이름 변경 포함):
  - `full_coverage_correct_rate`: 해당 유형에서 모델의 **모든 문항이 settled일 때만** 값이 있고, 아니면 null, `coverage_status: 미확정`.
  - `official_eligible`: AI 유형은 항상 false. AI 판정으로 전체 판정이 끝나도 공식 점수가 아니다. human/expert 중 어떤 범위를 공식으로 볼지는 프로토콜 소유자(총괄)가 정한다.
  - `diagnostic_correct_rate_over_settled`: settled 문항만 분모로 하는 **부분 검수 진단치**(기존 `correct_rate_over_reviewed`를 이름으로 명시).
  - `correct_rate_range = [settled 정답 / 전체 문항, (settled 정답 + 미확정 문항) / 전체 문항]`: 미검수·불확실·의견충돌 문항이 나중에 모두 오답 또는 모두 정답으로 판정될 때 전체 정답률이 가질 수 있는 정확한 하한·상한. 점수가 아니라 범위다.
  - 실행 실패(예외·입력 초과), 잘림, `context_limited` 문항은 모든 분모에 남는다.
