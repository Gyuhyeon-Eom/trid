## (1) HWPX 이미지 제외 대체 경로: 안전 제한 유지

**구현** (`collect_admrul_attachments.strip_hwpx_images`)
- 원본 zip의 중앙 디렉터리만 읽고 검사한다. 압축 해제는 하지 않는다.
- 아래 중 하나라도 걸리면 거부한다.
  - 전체 엔트리 10,000 초과 (kordoc의 미디어 많은 컨테이너 상한 `MAX_ZIP_ENTRIES2`)
  - 이미지 외 엔트리 500 초과 (kordoc HWPX 상한 `MAX_ZIP_ENTRIES`)
  - 선언 비압축 총량 256 MiB 초과. 이미지까지 포함해 센다 (kordoc HWPX `MAX_DECOMPRESS_SIZE`)
  - 1 MiB 넘는 엔트리의 압축비 100 초과 (B 기준. 실제 매뉴얼의 최대값은 31.7)
  - 절대경로, `..`, 역슬래시, 드라이브 경로 (zip-slip)
  - 심볼릭 링크
  - 암호화 비트
  - 중복 이름
- 남기는 엔트리는 1 MiB 단위로 복사하고, 선언 크기를 넘으면 거부한다. `BinData/`는 압축을 풀지 않는다.
- 사본은 kordoc을 다시 거치므로 kordoc 자체 제한(엔트리 500, 256 MiB)이 한 번 더 걸린다.
- kordoc이 원본을 거부하는 기존 조건은 그대로다. 대체 경로는 kordoc이 `ZIP_BOMB`을 낸 HWPX에만 들어간다.
- 거부되면 본문은 비고 라벨이 `kordoc_failed:zip_entry_limit; image-strip fallback refused: <이유>`가 된다.

**누락을 숨기지 않게 바꾼 것**
- B-025는 `[이미지: imageN]` 자리표시를 지웠다. 이번에는 `[그림 생략: imageN]`으로 남긴다.
- 실제 매뉴얼에서 이 표시가 423곳에 남는다.
- 추출기 라벨에 뺀 이미지 수와 크기, 그림 참조 수, "figure content not extracted"를 적는다. 실제 값은 1,239개, 13,298,442 bytes, 참조 423곳이다.
- guides 행에 `flags: figure_content_missing`과 `meta.figures_omitted=423`을 넣었다.
- **본문 완전성은 보장하지 않는다.** 그림 안의 표·도식 내용은 빠졌고, 원본과 대조하지 않았다.

**실제 확인**

| 항목 | 결과 |
|---|---|
| 실제 매뉴얼(엔트리 1,267개) 전체 경로 | 110,160자 추출, 라벨·표시 확인 |
| 같은 파일에 64 MiB 영(0) 엔트리를 더한 악성 고압축 fixture | kordoc `ZIP_BOMB` 후 대체 경로가 `compression ratio above 100`으로 거부, 본문 0 |
| 같은 파일에 `../../evil.xml`을 더한 fixture | `unsafe zip entry path`로 거부 |
| 단위 테스트 `tests/test_b026_hwpx_strip.py` 6개 | 이미지 1,200개 파일은 본문 엔트리를 바이트 그대로 보존. 고압축·경로 5종·암호화·중복·엔트리 수·총량 거부 |

- **미확인:**
  - 실제 암호화 HWPX와 zip64 파일로는 시험하지 않았다. 암호화는 테스트에서 헤더 비트를 직접 세워 확인했다.
  - kordoc 내부 XML 처리(XXE 등)는 이번 변경과 무관해 검토하지 않았다.
  - 일반 경로에서 `![image](…)` 줄을 지우는 기존 동작은 이번 범위가 아니어서 그대로 두었다. 이미지 제외가 아닌 다른 문서도 그림 속 정보는 원래 추출되지 않는다.

## (2) 예약 부분 겹침 3건: 구간 단위 법령 공통 검토 → 3건 모두 보류 유지
