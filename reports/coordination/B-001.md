## 6. 기준선 대비 결과

데이터 작업이라 모델 성능 기준선은 해당 없다. 비교 대상은 같은 원본을 다루는 A의 `prepare_fineweb2_ko.py`다.

| 항목 | A `prepare_fineweb2_ko.py` | B `collect_fineweb2_ko.py` (clean v0) |
|---|---|---|
| 다운로드 | Mac/실행 위치에서 HF `main`을 받음(revision 미고정, 파일 sha256 기록) | AWS 내부에서 고정 revision을 받고 원본 parquet를 S3 raw에 영구 보관 |
| 정제 | NFC → `clean_lines` → 한글 비율 필터 → 특수 토큰 문자열 제거 → 평가 8-gram 제거 → ko-pii 치환 | NFC만 적용. 행 스키마 변환 |
| 산출 | trid 8k 토크나이저 uint16 `.bin` + manifest (원문 행 없음) | 출처 URL·날짜·dump·sha256를 담은 clean 행 (토큰 없음) |
| 분할 | valid = HF `test` 분할에서 3,000문서 | 미지정 |

두 스크립트는 다운로드와 정제가 겹치고, B가 아직 PII·한글 비율 정제를 하지 않는다. 아래 계약으로 경계를 하나로 정할 것을 제안한다. 총괄 검토 전에는 A 파일을 수정·삭제하지 않는다.

## 제안: 단일 raw → clean → tokens 계약 (`corpus-contract v1`)

근거 초안: `/tmp/trid-open-baseline/corpus-contract.md`. 채택되면 저장소 `docs/`에 옮길 위치는 총괄이 지정해 주기를 요청한다.

### raw (B 소유, 불변)
`s3://trid-training-148761639313/corpus/raw/<source>/…`에 원본 바이트를 그대로 둔다(parquet·HTML·PDF·HWP/HWPX). 원본 URL 또는 데이터셋 revision과 파일 sha256을 provenance에 기록한다. 덮어쓰지 않는다.

### clean (B 소유)
`corpus/clean/<source>/docs-*.jsonl.gz`(샤드당 약 2억 자), `stats.json`, `provenance.json`, `ATTRIBUTION.txt`.

행 필드:

| 필드 | 내용 |
|---|---|
| `id` | `<source>:<원본 id>`, 재실행해도 같음 |
| `group` | 중복 판정·분할 단위 |
| `kind`, `title`, `text` | NFC 텍스트, 문단은 `\n` |
| `source` | 원문 URL |
| `license`, `attribution` | 사용권과 출처 표시 문구 |
| `date` | 날짜 |
| `sha256` | `text`의 해시 |
| `collected_at`, `extractor` | 수집 시각, 추출 방법 |
| `meta` | 출처별 부가 정보 |
| **`split`**(v1 추가) | `sha256("split:"+group)` 버킷으로 test 0.5%, valid 0.5%, 나머지 train. FineWeb-2는 HF `test` 분할을 별도 `split: valid_upstream`으로 변환 |
| **`clean_version`**(v1 추가) | 예: `"clean-v1"` |
| **`flags`**(v1 추가) | 탈락 사유 대신 남기는 품질 표시 |

B가 clean 단계에서 하는 일. 토크나이저와 혼합 비율에 의존하지 않는 출처 단위 처리만 맡는다.
1. NFC, `trid.korean_quality.clean_lines`(C4식 줄 정리).
2. 한글 비율 필터(`FINEWEB2` 기준). 탈락 문서는 출처별 사유 통계에만 남긴다.
3. `trid.korean_quality.redact`(ko-pii) 치환. 표본상 FineWeb 문서의 12~17%에 이메일·전화가 있다. 이 단계에서 처리해 S3 clean 텍스트에 개인정보가 남지 않게 한다. 출처별 탐지 수는 `stats.json`에 기록한다.
4. 출처 내부 완전 중복 제거(NFC + 공백 제거 문자열의 sha256, 먼저 나온 행 유지).
5. 사용권 판정. 공공누리 제1유형, 저작권법 제7조 대상, 또는 데이터셋 사용권이 허용하는 경우만 본문을 저장한다. 그 밖에는 `catalog-*.jsonl.gz`에 메타데이터만 둔다.
- 2·3번은 A의 함수와 같은 구현을 호출하므로, A가 clean을 입력으로 쓰면 결과가 같아진다.

### tokens (A 소유)
B의 clean 샤드를 입력으로 받는다. A가 하는 일:
1. 출처 간 완전·근사 중복 제거(MinHash, 출처 우선순위). 예: FineWeb의 ko.wikipedia 6%는 기존 위키 출처와 겹친다.
2. **평가 오염 제거.** 평가 문서를 소유하지 않는 A·B가 원문을 보지 않도록, 총괄이 평가 텍스트의 8-gram 해시 목록만 전달하는 방식을 제안한다. 최종 비공개 평가 정답은 A·B에 공개하지 않는다는 규칙과 맞추기 위해서다. 현재 A 스크립트는 개발 평가 원문을 직접 읽는다.
3. 토크나이저 적용, 출처별 토큰 예산·가중치, `.bin`/manifest 작성.
- A 스크립트에서 다운로드·정제 부분은 clean 입력으로 바꾸면 빠진다. 바꿀지는 A와 총괄이 정한다.

### 공통
- 재개는 출처별 `corpus/state/<source>/`(완료 표시·샤드별 id 목록)로 한다.
- 수집 속도는 1초당 1요청 이하로 하고 robots.txt를 준수한다.
- 자격증명은 출력하지 않는다.
- AWS 실행 기록(작업명·인스턴스·종료 조건)은 해당 출처의 provenance에 남긴다.

## 7. 해석의 한계·미해결 문제

- FineWeb 표본은 파일 1개 안의 샤드 4개 앞부분이다. 25개 파일 전체의 분포(연도·도메인)를 대표하지 않는다. 지금 clean v0은 PII와 한글 비율 정제 전이므로, 이 상태로 학습에 투입하면 안 된다.
- FineWeb 1개 파일의 raw(4.8GB)와 clean(약 4.6GB gzip)이 모두 S3에 있다. 25개 전체는 S3 약 230GB 규모다[추정].
- 국회 회의록 전체 회의 수와 문자 수는 22대 상임위 탐색이 끝나야 외삽할 수 있다. 1초당 1요청으로 전 대수를 받으면 수만 건에 하루 이상 걸린다[추정].
- 22대 국정감사 회의록 본문 품질은 아직 확인하지 않았다(목록만 탐색 중).
- 수집기 병렬화가 하위 에이전트 사용량 한도로 막혀 있다.
