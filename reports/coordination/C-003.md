## 7. 대규모 평가 하네스 점검 (BENCHMARK-SCALE-001 C 준비 결과)

기존 개발 자료(RAG310 프롬프트, 반복 사용된 진단용)로 실제 중단·재개를 실행했다. 출력은 채점하지 않았다. 증거: `harness-check.json`.

| 경로 | 시험 | 결과 |
|---|---|---|
| trid 자유 생성 `train_public_dialogue evaluate --prompts` | 310문항, 40초 후 강제 종료 → 같은 명령 재실행 | 종료 시 263행 기록·최종 보고 미작성, 재실행은 남은 47행만 생성, 최종 310행·중복 0·프롬프트 순서 일치, 잘림 2·예외 0 집계 |
| 공개 모델 자유 생성 `evaluate_external_chat --freeform-prompts` | 40문항(Kanana), 60초 후 강제 종료 → 재실행 | 종료 시 26행, 최종 40행·중복 0·순서 일치, EOS 40 |
| 거부 동작 | 단위 테스트 + 실행 | 다른 설정의 partial 혼합 거부, 미완료 최종화 거부, 완료 보고 덮어쓰기 거부 |

점검 중 발견해 수정한 문제: (1) 두 자유 생성 경로 모두 마지막에만 결과를 써서 중단 시 전체 손실, (2) trid 경로는 한 문항 예외가 전체 실행을 중단, (3) trid 런타임은 입력+한도>1,024를 예외로 거부하므로 고정 한도로 대규모 실행 시 긴 문서가 실패. 이제 문맥 잔여로 상한을 두고 `context_limited`·`truncated_output`·`exception`을 항목별로 남긴다.

남은 한계(2,000문항 규격 대비):
- 값 형식 RAG310 경로(`evaluate_external_chat` 조건별 실행, `evaluate_rag_eval.py`)는 이번에 journal을 연결하지 않았다. 최종 시험은 서술형 의미 채점이 주지표이므로 자유 생성 경로를 우선 보강했다.
- 최종 시험 실행에는 모델별 처리 시간이 필요하다. 이번 실측 기준 공개 모델 1.7~2.1B Q8_0 Mac Metal 단일 슬롯에서 설명형 문항당 약 10~15초 → 2,000문항 × 2모델 약 11~17시간(추정). 별도 GPU 서버 또는 병렬 슬롯 사용 시 단축 가능.
- trid 1,024 문맥은 긴 근거 문서와 256토큰 설명을 동시에 담지 못할 수 있다(이번 최소 여유 198). 문맥 초과 항목 수를 최종 시험에서 별도 보고해야 한다.
- 채점기(결론·근거·조건·허위 주장)는 아직 사람·전문가 판정 절차가 없다. 이번 판정은 AI 검토다.
